# 윈도우 첫 실행 점검표 (v1.0.0)

맥에서는 검증했지만 **윈도우에서는 한 번도 안 돌려본 것들**만 모았다.
순서대로 하고, 어긋나는 게 있으면 맨 아래 "보내줄 것"을 챙긴다.

⚠️ **파괴적인 검사(7·8번)는 맨 뒤에 있다.** 순서를 지킬 것.

---

## 0. 받기

GitHub Actions 실행 결과 아래 **Artifacts → `dist-windows-latest`** 를 받는다.
**`.zip`으로 내려온다** — 압축을 풀면 `STARLOG-Setup-1.0.0.exe`가 나온다.

---

## 1. SmartScreen

exe를 더블클릭한다.

> **나와야 하는 것** — `Windows에서 PC를 보호했습니다` → **[추가 정보]** → **[실행]**

서명을 안 했으니 이게 정상이다. [추가 정보]가 안 보이면 창을 넓히거나 스크롤한다.

- [ ] 경고가 뜨고, [추가 정보] → [실행]로 진행됨

---

## 2. 설치 화면

> **나와야 하는 것** — 설치 경로를 **고를 수 있는** 화면. `[찾아보기]` 버튼이 있다.

`oneClick: false` 설정이 먹었는지 보는 것이다. 아무것도 안 묻고 바로 설치되면
설정이 안 먹은 것이다.

- [ ] 경로 선택 화면이 나옴
- [ ] 설치 완료 후 **시작 메뉴와 바탕화면에 STARLOG 아이콘**이 보임 (검은 사각형 + 흰 스파크)

---

## 3. 입구 화면

앱을 실행한다.

> **나와야 하는 것** — 검은 배경에 **모드 선택 화면**(로컬 / 클라우드).

이 화면은 백엔드 없이 `app://`로 뜬다. **빈 검은 창만 나오면** 그게 고장이다.

- [ ] 입구 화면이 정상적으로 보임

---

## 4. 로컬 세이브 만들기 — **가장 중요**

**[로컬 모드]** → 새 세이브 → 이름을 **`윈도우 테스트`** 로 준다 (한글 확인 겸용).

> **나와야 하는 것** — 잠깐 로딩 후 **대시보드**. `Welcome back, Scribe!`가 보인다.

여기가 통과하면 **번들 `java.exe`를 찾았고 백엔드가 떴다**는 뜻이다.
이게 이 점검표의 핵심이다.

- [ ] 대시보드가 뜸
- [ ] 좌측 상단 STARLOG, 상단에 DASHBOARD / LIBRARY / ADD

### 실패했다면

화면에 뜬 **오류 코드**(`JAVA_NOT_FOUND`, `JAR_MISSING`, `DB_IN_USE` 등)를 적어둔다.

---

## 5. 파일이 어디에 생겼나

탐색기 주소창에 그대로 붙여넣는다:

```
%APPDATA%\starlog
```

> **있어야 하는 것**
> ```
> settings.json
> connections.json
> backend.log
> data\saves\윈도우 테스트.mv.db      ← 한글 파일명이 안 깨져야 한다
> data\backups\
> ```

⚠️ 폴더 이름이 `STARLOG`(대문자)면 알려달라 — 맥에서 고친 부분이 안 먹은 것이다.

- [ ] `%APPDATA%\starlog` 안에 위 파일들이 있음
- [ ] 세이브 파일 이름의 한글이 안 깨짐

---

## 6. 기능 한 바퀴

깊게 안 봐도 된다. **화면이 뜨고 눌리는지**만.

- [ ] `LIBRARY` 들어가짐
- [ ] `ADD` 들어가짐 (게임 검색은 IGDB 키가 없으면 안 된다 — 정상)
- [ ] 우측 상단 프로필 → **시스템** 화면 들어가짐
- [ ] 창 크기를 바꾸고 껐다 켜면 **그 크기로 다시 뜸**

---

## 7. ⚠️ 좀비 `java.exe` — 이게 진짜 목적

세이브를 연 상태(대시보드)에서:

1. **작업 관리자**를 연다 (`Ctrl+Shift+Esc`)
2. **[세부 정보]** 탭으로 간다
3. 목록에 **`java.exe`가 있는지 확인**한다 → 있어야 정상이다 (백엔드다)
4. **`STARLOG.exe`를 골라 [작업 끝내기]** 로 강제 종료한다
5. **5초 세고**, 목록을 새로고침(`F5`)한다

> **나와야 하는 것** — `java.exe`가 **사라져 있어야 한다.**

남아 있으면 `ParentWatchdog`가 윈도우에서 안 도는 것이다.
그놈이 세이브파일을 쥐고 있어서 **다음에 열 때 백업이 찢어진다** —
네가 계속 겪던 세이브 손상이 이 구조다.

- [ ] 강제 종료 5초 뒤 `java.exe`가 사라짐
- [ ] 남아 있으면 → **[ 남아 있었다 ]** 라고 적어둘 것

---

## 8. 바로 다시 열기

7번 직후(수동으로 `java.exe`를 지우지 말고) 앱을 다시 실행하고
**같은 세이브(`윈도우 테스트`)를 연다.**

> **나와야 하는 것** — 그냥 열린다.

`DB_IN_USE`가 뜨면 앞의 좀비가 파일을 쥐고 있는 것이다.

- [ ] 다시 열림
- [ ] `DB_IN_USE`가 떴다면 그 화면을 캡처

---

## 보내줄 것

문제가 있었으면 이 셋을 챙긴다.

1. **몇 번에서 틀어졌는지**와 화면에 뜬 **오류 코드/문구**
2. **로그 파일** — 아래를 탐색기 주소창에 넣고, 열린 파일의 **마지막 100줄**
   ```
   %APPDATA%\starlog\backend.log
   ```
3. 화면 캡처 (있으면)

전부 통과했으면 **"윈도우 전부 통과"** 한마디면 된다.
