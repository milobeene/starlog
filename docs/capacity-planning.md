## 1. 각 티어의 진짜 병목

| 서비스 | 무료 한도 | 우리에게 병목인가 |
|---|---|---|
| **IGDB** | **초당 4요청 / 동시 열린 요청 8개**. 초과 시 429 | ⚠️ **여기가 유일한 실질 병목** |
| **Render** | 750 인스턴스-시간/월, **15분 무활동 시 스핀다운** | 스핀다운이 문제(콜드 스타트), 시간은 여유 |
| **Neon** | **0.5 GB 스토리지**, 100 CU-시간/월 | 스토리지가 먼저 찬다 |
| **Cloudflare R2** | **10 GB**, 쓰기 100만/월, 읽기 1000만/월 | 사실상 무제한 |

### 왜 IGDB만 병목인가

R2 10GB는 커버 이미지 기준 **수만 장**이다. Neon 0.5GB는 텍스트만 담으니 항목 수만 건이다.
반면 IGDB는 **초당 4요청**이라 사용자 3명이 동시에 검색창에 타이핑하면 그것만으로 닿는다.
게다가 우리는 검색이 디바운스 300ms라 타이핑 한 번에 요청 하나가 나간다.

**중요**: IGDB 한도는 **회원당이 아니라 앱 전체(우리 클라이언트 ID)당**이다.
그래서 "유저당 N회" 같은 배분보다 **전역 처리율 제한**이 먼저다.

## 2. 권고안

### A. 전역 IGDB 호출 게이트 (우선순위 1)
`HttpIgdbClient` 앞에 **초당 4건 토큰 버킷 + 동시 8건 세마포어**를 둔다.
- 넘치면 짧게 대기 후 재시도, 그래도 안 되면 `503`으로 안내
- 429를 받으면 **백오프**하고 그 사이 요청은 큐에 세운다
- 지금은 429가 그대로 502로 올라가 사용자에게 "외부 DB 오류"로 보인다

### B. 회원당 검색 쿼터 (우선순위 2)
전역 게이트만 있으면 한 사람이 다 쓸 수 있다. **분당 20회 / 일 200회** 정도로 상한.
승인제로 회원 수가 통제되므로 이 정도면 충분하다.

### C. 커버 업로드 상한 (우선순위 3)
R2는 여유롭지만 **회원당 총량**은 두는 게 좋다 — 한 명이 10GB를 채우면 전원이 막힌다.
회원당 200MB 정도면 커버 수백 장이라 실사용에 안 걸린다.

### D. Render 스핀다운 대응
15분 무활동이면 잠들고 다음 요청이 **수십 초** 걸린다. 지인 몇 명이 가끔 쓰는 패턴이면
거의 항상 콜드 스타트를 만난다. 두 갈래:
- 프론트에 "깨우는 중" 안내를 띄운다 (정직하고 공짜)
- 외부 크론으로 주기적 핑 (750시간을 소진하므로 상시는 불가 — 계산 필요)

## 3. /admin 모니터링 (요청사항)

**최소 구현**: 이미 `AuditLog`가 관리자 경로를 기록한다. 여기에 붙이면 화면 하나로 끝난다.

| 지표 | 어디서 얻나 |
|---|---|
| IGDB 호출 수 (검색/상세) | `HttpIgdbClient`에 카운터. 게이트를 만들면 거기서 같이 센다 |
| 429 발생 수 | 〃 |
| 회원별 검색 횟수 | 쿼터 구현 시 그 카운터를 그대로 노출 |
| 서버 요청 수·응답 시간 | Spring Boot Actuator + Micrometer (`/actuator/metrics`) |
| R2 사용량 | `CoverImage.sizeBytes` 합계 — **DB만으로 계산된다** |
| Neon 스토리지 | `pg_database_size()` 쿼리 |

**추천**: Actuator를 붙이고 `/admin`에 "시스템" 탭을 신설. 외부 모니터링 도구는 무료 티어에서
또 다른 의존이라 **DB와 인메모리 카운터로 끝내는 게** 이 규모엔 맞다.

## 4. 지인 몇 명 기준 — 그 외 고려점

- **R2 고아 파일**: 커버 발급만 하고 업로드 안 하면 presign된 키가 안 쓰인 채 남는다.
  버킷 라이프사이클 규칙(예: 태그 없는 객체 7일 후 삭제)을 걸어두는 게 좋다
- **Neon 0.5GB**: 텍스트만이라 여유롭지만, `audit_log`가 단조 증가한다.
  이미 1년 보존 배치가 있고 인덱스도 이번에 붙였다
- **Render 무료 DB는 30일 후 만료** — 우리는 Neon을 쓰므로 해당 없음. Render는 웹 서비스만
- **동시 접속**: `SessionRegistry`가 **JVM 메모리**라 인스턴스가 늘면 세션 무효화가 깨진다.
  무료 티어는 단일 인스턴스라 지금은 성립 (NFR-O3에 이미 기록됨)
