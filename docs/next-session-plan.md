**왜 최우선인가** — 반응형·PWA·일렉트론이 전부 이것의 하류다. 폰에서 열어봐야 반응형을 고칠 수 있고,

### 2-1. 백엔드 → Render  [사용자 작업 + 내 작업]

**사용자가 할 것** (내가 못 하는 것: 계정·대시보드·환경변수 입력)
1. Render에서 `New > Web Service` → 이 저장소 연결 → **Root Directory `backend`**
2. **Docker 방식이다** — Render는 Java 네이티브 런타임이 없다(Node/Python/Ruby/Go/Rust만 있음).
   Root Directory를 backend로 잡으면 Render가 자동으로 Dockerfile을 찾아 Docker Build Context /
   Dockerfile Path를 `backend/`로 제안한다. `backend/Dockerfile`(멀티스테이지: JDK로 빌드,
   JRE로 실행)을 이미 만들어뒀고 로컬 `docker build` + 컨테이너 기동으로 검증 완료
3. Language 필드가 Node로 자동 감지되면 무시해도 된다 — Root Directory를 backend로 지정하는
   순간 Docker 옵션으로 바뀐다. Build/Start Command 칸은 Dockerfile이 대신하므로 비워둔다
4. Compute Plan은 **Free** — 계획 전제가 무료 티어다 (그래서 O-4로 세션을 DB로 옮겼다)
3. 환경변수 입력:

| 키 | 값 |
|---|---|
| `SPRING_PROFILES_ACTIVE` | `prod` |
| `DATABASE_URL` / `DATABASE_USERNAME` / `DATABASE_PASSWORD` | Neon 대시보드 값 (`application-local.yml`에 있음) |
| `IGDB_CLIENT_ID` / `IGDB_CLIENT_SECRET` | 〃 |
| `STORAGE_ENDPOINT` / `STORAGE_BUCKET` / `STORAGE_ACCESS_KEY` / `STORAGE_SECRET_KEY` / `STORAGE_PUBLIC_BASE_URL` | 〃 (R2) |
| `RESEND_API_KEY` | 〃 — ⚠️ **채팅에 평문 노출된 적 있음. 회전 권장** |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | 〃 |
| `ADMIN_EMAIL` / `ADMIN_PASSWORD` | 관리자 부트스트랩. `milo.beene@gmail.com`을 넣으면 **기존 회원을 승격**한다(멱등) |
| `CORS_ALLOWED_ORIGINS` | Vercel 주소 (2-2 후에 채운다) |
| `FRONTEND_BASE_URL` | 〃 |
| `SIGNUP_EMAIL_ALLOWLIST` | 기본값 그대로면 생략 |

**내가 할 것**: `application-prod.yml`에 아직 없는 키가 있으면 채우고, 기동 로그로 검증.

### 2-6. ~~배포 후 종단 검증~~ — ✅ **2026-08-26 완료**

| 항목 | 결과 |
|---|---|
| 이메일 로그인 / 구글 로그인·연동 | ✅ (DB 대조까지) |
| 담기 → 회차 → 취득 → 통계 | ✅ 실데이터 76건 임포트로 전 경로 통과 |
| 커버 업로드 | ✅ R2 CORS 설정 후 확인 |

**커버 업로드가 막혔던 이유** — 브라우저가 R2로 **직접 PUT**하는데 그건 단순 요청이 아니라
(PUT + Content-Type) 프리플라이트가 먼저 나간다. R2 버킷에 CORS 정책이 없어 403이었다.
Cloudflare R2 대시보드에서 아래를 넣어 해결했다:

```json
[{ "AllowedOrigins": ["https://starlog-xi.vercel.app", "http://localhost:3000"],
   "AllowedMethods": ["PUT"], "AllowedHeaders": ["content-type"], "MaxAgeSeconds": 3600 }]
```

`GET`이 없는 이유 — 이미지는 `<img>`로 불러오는데 그건 CORS 대상이 아니다.
`content-type`이 필요한 이유 — 그 값이 presigned 서명에 포함돼 있어, 다른 값으로 올리면 R2가 403을 준다.

> **이미지가 어디 저장되나** — 개인 커버만 R2다. 마스터 커버·배너는 IGDB CDN(`images.igdb.com`)에서
> 오고 우리 서버를 안 거친다. DB에는 `coverImageId`만 있고 화면이 크기별 URL을 조립한다

### 2-7. 배포 후 성능 — **콜드스타트는 수용하기로 확정 (2026-08-26)**

실측: 로컬 3ms / 배포 깨어있음 **150ms** / 잠들었다 깨면 **최대 50초+**.

150ms의 내역 — 한국→Cloudflare 엣지(오사카) ~50ms, 엣지→Render 싱가포르 ~80ms, 앱 ~20ms.
**Render 무료는 리전에 도쿄·서울이 없어** 싱가포르가 이미 최선이다. 이 왕복은 구조적이라 못 줄인다.

**핑으로 깨워두는 우회는 하지 않는다.** Render 공식 문서에 외부 핑에 대한 언급은 없고
(제재 조항은 서비스가 **내보내는** 트래픽에 대한 것뿐이라 명시적 위반은 아니다),
그럼에도 Render가 제시하는 해법은 유료 인스턴스뿐이다 — 15분 슬립이 무료 티어의 가격 근거라
명시 금지가 없어도 의도에 반한다. 실사용이 늘어 정말 불편해지면 **$7 Starter가 정직한 답**이다.
(덤: 잠든 동안 `/robots.txt` 요청은 Render가 가로채 직접 응답해서 깨우지도 못한다)

### 배운 것 — `mix-blend-mode`는 **요소 자신에** 걸어야 한다

헤더 글자를 배경에 따라 반전시키는 데 세 번 헛짚었다. 전부 같은 원인이었다.

- **자식에 걸면 안 된다.** z-index가 붙은 조상은 쌓임 맥락을 만들고, 자식의 블렌딩은
  그 맥락 **안에서만** 일어난다 — 헤더의 투명 배경하고만 섞여 아무 일도 안 생긴다
- **요소 자신에 걸면** 그 요소의 backdrop(부모 맥락에서 먼저 그려진 전부)과 섞이므로
  z-index를 줘도 된다. z-index를 뺐다가 본문이 헤더 위로 올라와 클릭을 가로챈 것도 이것 때문이었다
- **자식은 조상의 블렌딩에서 빠져나올 수 없다.** 드롭다운 패널이 형광색으로 뒤집히는 걸 막으려면
  `createPortal`로 body에 빼야 한다 (`Dropdown`의 `portal` 옵션, 기본 false)
- **흑백으로 떨어뜨리려던 시도는 폐기.** `backdrop-grayscale`로 블렌딩 전에 배경 채도를 빼면
  검정↔흰색이 되지만, 헤더 띠만큼 배경이 흑백이 되어 더 나빴다. 보색이 나오는 쪽을 택했다

### 리액트 19 린트가 잡아준 것 둘

`npm run lint`가 **경고가 아니라 에러**로 막았다. 둘 다 빌드는 통과하던 코드다.

- **`react-hooks/refs` / `purity`** — 입구 페이지에서 마운트 시각을 렌더 중에 찍고 있었다
  (`if (ref.current === 0) ref.current = Date.now()`). ref 쓰기도 `Date.now()`도 렌더를
  불순하게 만든다 → effect 첫 실행에서 찍는다. 마운트와의 차이는 몇 ms라 연출에 영향 없음
- **`react-hooks/set-state-in-effect`** — 설정 페이지의 "해제하는 중"을 effect에서 껐다.
  **상태가 아니라 파생값**이 맞다: `unlinkRequested && (me.data?.profile.googleLinked ?? true)`.
  effect로 끄면 렌더가 한 번 더 돈다

| `FluidBackground` | 항상 WebGL | 모바일·`prefers-reduced-motion`이면 정적 그라데이션 (배터리·발열) |

**이미 되어 있어 손댈 것 없는 곳**: `DataTable`(`overflow-x-auto`), 상세 페이지(`lg:grid-cols-3`),
라이브러리 그리드(`2 → 3 → 4 → 6 → 8` 램프).

## 작업 4-2. 배경 색상 설정 [v0.1 이후]

배경(FluidBackground)의 색을 **사용자가 고를 수 있게** 한다. 지금은 코드에 박혀 있다.

### 조절 가능한 값 — 색 5개 + 숫자 5개

| | 지금 값 | 뜻 |
|---|---|---|
| `colorA`~`colorE` | `#E8975A` `#F7D6A0` `#9BAAB8` `#7A9448` `#1E262B` | 기조 / 밝은 대비 / 옅은 색 / 중간 강조 / 어두운 바닥 (한강 노을) |
| 흐름 속도 (입구 / 앱) | `0.1` / `0.067` | 유체가 흐르는 빠르기. 앱은 1.5배 느림 |
| 순회 주기 | `0.08` | 색이 한 바퀴 도는 시간 |
| 무지개 채도 | `0.45` | 색이 얼마나 진한가 |
| HSL 명도 | `0.65` 고정 | 무지개의 밝기 |

### 결정

- **색 5개만 노출한다.** 숫자 5개는 서로 얽혀 있어 하나를 만지면 다른 인상이 같이 바뀐다 —
  실제로 순회 속도를 올렸더니 "흐름이 달라졌다"는 지적을 받았고, 명도를 흐름 노이즈에
  태웠더니 색 순회가 안 보이게 됐다. 사용자가 만지면 대부분 나빠진다
- **프리셋 + 커스텀 둘 다.** 프리셋만으로는 답답하고, 커스텀만 있으면 망치기 쉽다.
  프리셋 후보는 이미 셰이더 주석에 다섯 벌이 기록돼 있다
  (원본 오렌지 / 에메랄드 / 이끼와 황동 / 심해 / 숲과 노을 / 한 톤 초록 / 한강 노을)
- **저장은 `member`에 JSON 컬럼 하나.** 프리셋 여러 개를 저장하는 별도 테이블은 지금 필요가 없다.
  나중에 원하면 그때 테이블로 승격한다 → **V3 마이그레이션**
- 로컬 앱(v1.0)으로 가면 이 설정은 계정이 아니라 **앱 설정 파일**로 옮긴다

## 작업 6. IGDB 안내 + 일일 쿼터 + /admin 시스템 탭

근거와 수치는 `docs/capacity-planning.md`에 있다. 요약:
- **IGDB만 실질 병목** (초당 4 / 동시 8, **앱 전체 기준**). R2·Neon은 여유
- 지금은 429가 502로 올라가 "외부 DB 오류"로 보인다

### 6-1. IGDB 한도 초과 시 동작  [확정]
**기다리지 않고 즉시 안내한다.** 큐·재시도 없음.
문구는 "잠시 후"가 아니라 **"지금 여러 분이 동시에 검색 중입니다. 바로 다시 시도해 주세요."**
— 초당 4건이라 실제로 1초 안에 풀린다. 기다리게 하면 오히려 멈춘 것처럼 보인다.

### 6-2. 회원당 일일 쿼터  [확정 — 사용자 요청]
**"모르고 막히는 것"보다 "하루에 몇 건까지인지 보이는 것"이 낫다**는 방침.
최대 사용자 10명 기준으로 잡는다.

| 대상 | 일일 한도(회원당) | 근거 |
|---|---|---|
| IGDB 검색 | 200 | 앱 전체 초당 4건. 한 세션에 20~30건이면 충분 |
| 게임 담기(마스터 다운로드) | 50 | IGDB 상세 호출 + 마스터 생성이라 검색보다 무겁다 |
| 커버 업로드 | 20건 / 총 200MB | R2 10GB ÷ 10명 = 1GB지만 여유를 크게 둔다 |

- **카운터는 DB에 저장한다** (`usage_quota(member_id, date, kind, count)`).
  인메모리로 두면 Render가 15분마다 재시작해 쿼터가 무의미해진다 → **V2 마이그레이션에 포함**
- **설정 화면에 남은 쿼터를 표시한다** — "오늘 검색 180/200" 식. 이게 이 방침의 핵심이다
- 서버 요청 **전체**에 대한 캡은 두지 않는다 — 페이지 한 번 여는 데 5요청이 나가서
  숫자가 사용자에게 의미를 못 주고, Render·Neon 한도는 요청 수가 아니라 **가동 시간·컴퓨트 시간**이다

### 6-3. /admin 시스템 탭
IGDB 호출 수·429 발생 수·회원별 쿼터 소진·R2 사용량(`CoverImage.sizeBytes` 합)·
Neon 스토리지(`pg_database_size()`). Actuator를 붙이되 **외부 모니터링 도구는 안 쓴다**.

  `mix-blend-mode`, 포탈 드롭다운의 좌표 계산, 로컬 폰트 파일 서빙. 셋 다 빌드는 통과하면서

  자주 들어가면 콜드스타트를 거의 안 만나고, 3일에 한 번이면 매번 만난다
- **IGDB 쿼터를 미룬 이유** — 사용자가 여럿일 때 의미가 생긴다. 혼자면 초당 4건에 닿을 일이 없다
- **배경 색상 설정이 v0.1 밖인 이유** — 있으면 좋은 것이지 없으면 못 쓰는 것이 아니다

## 실데이터 투입 — ✅ **2026-08-26 완료 (76건)**

옵시디언 볼트(`~/Core Vault/03. Collection/Games`) md 78개 → 인덱스 1개 제외 77건 →
마리오 3D 월드 + 퓨리 월드 병합으로 **76건** 투입.

- **마스터는 IGDB.** 볼트 제목이 한글이라 IGDB(영문 DB) 검색이 안 돼서, 영문 제목을 대고
  찾은 뒤 **볼트 출시일과 대조**해 76/76 전건 검증했다. 매칭표는 `docs/igdb-match.md`
- **표시명은 볼트 한글명**을 오버라이드로 넣어 `displayName`이 거기서 파생되게 했다.
  IGDB의 한글 별칭은 대부분 약칭(`젤다 야숨`, `모동숲`)이라 표시명으로 못 쓴다
- 넣은 것: 제목·평점·취득(가격/플랫폼/계정/날짜)·회차(기간/기기/에뮬/입력수단/계정)·개인 장르
- 안 넣은 것: 커버·개발사·출시일 — IGDB 마스터가 대신 갖는다
- 검수: 항목 76 / 취득 76 / 회차 64 / 지출 합계 1,885,530원 — 볼트 원본과 일치

**임포트가 드러낸 것 넷**
- `paused: true`를 회차 전부에 적용하면 2024년에 끝낸 회차까지 중단이 된다 → 최근 회차에만
- `바이패드`는 IGDB에 없었다. 커버 파일명 `cover-biped.jpg`가 단서였다 (Biped)
- 매칭을 날짜 근접도만으로 고르면 DLC·버전판을 집는다 → **이름 정확 일치를 우선**
- 볼트 원본 결함: 몬헌 2건의 장르에 **문자 그대로** `\t\r`이 박혀 있었다(제어문자가 아니라
  백슬래시 두 글자라 `strip()`으로 안 지워진다)

**취득일·플레이시간이 비어 있는 이유가 밝혀졌다** — 임포터 버그가 아니라 **원본 md에 그 필드가 없다.**
