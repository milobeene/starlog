## ✅ 5단계 — 입구 화면 + 로컬 모드 (2026-08-28 완료)

**v1.0의 심장.** 여기서 처음으로 "내 앱"이 아니라 **"각자의 앱"**이 된다.
근거: architecture §1(두 모드) · §2(늦게 띄우기) · §3(다섯 갈래) · §5(데이터 루트) · §7(자격증명)

- 입구 화면을 **일렉트론이 `app://`로 직접 로드** — 백엔드보다 먼저
- **[로컬 모드] / [클라우드 모드]** 두 갈래

- 일렉트론 ↔ 화면 **IPC** — 이 앱에서 백엔드를 안 쓰는 유일한 통로
- **H2 파일 DB = 세이브파일 그 자체**
- **다섯 갈래 진단**을 스프링이 판정하고 구조화된 코드로 죽는다
- 데이터 루트 폴더 구조 확정 (`saves/` `backups/` `covers/` `media/`)
- ⚠️ 윈도우 좀비 프로세스 확인 (`taskkill /T`)

> ### `/admin`을 해체하지 않고 성격을 바꾼다 — 2026-08-27
>
> 원래 계획은 `/admin`을 통째로 없애고 게임 마스터 편집만 일반 기능으로 올리는 것이었다.
> **바꾼 이유** — 해체하면 갈 곳 없는 것들이 남는다. **자격증명 · IGDB 사용량 ·
> 일괄 동기화 · 마스터 삭제**는 전부 "앱 전체" 층위라 개별 게임 화면에도, 프로필 설정에도
> 안 맞는다. 그 화면이 계획에 없었는데 `/admin`이 이미 그 자리에 있다.
>
> → **`/admin` → 시스템** (API 키 · 사용량 · 게임 마스터)
>
> **§9의 "🔴 `/admin` 시스템 탭 삭제"를 일부 철회한다.** 지울 것은 **남의 사용량**(쿼터)이지
> IGDB 호출 수 · 스토리지 용량 · DB 크기가 아니다. 1인 앱에서는 오히려 더 필요하다 —
> 내 키 한도, 내 버킷, 내 DB니까.
>
> ⚠️ **API 키 화면은 백엔드를 안 쓴다.** §7이 "스프링은 `connections.json`을 모른다,
> 읽는 건 일렉트론뿐"이라고 못 박았다. 그래서 이 화면은 **5단계가 깔아둔 IPC** 위에 선다.
> 5단계보다 먼저 만들면 껍데기만 짓고 다시 뜯게 된다.

## 부록 C — 9단계 결과 (2026-08-28)

### 🔑 `BACKUP TO`가 필요 없어졌다

§5는 "쓰는 중인 `.mv.db`를 `cp`로 복사하면 손상되니 H2 `BACKUP TO`를 쓰라"고 했다.
맞는 말이지만 **그건 DB가 열려 있을 때 이야기다.** 우리 구조에는 닫혀 있는 순간이
분명히 있다 — 백엔드를 띄우기 **전**, 즉 입구 화면이다.

거기서 복사하면 백업이 **세이브파일과 똑같은 `.mv.db`**로 남고, zip과 압축 해제가 통째로
사라진다. → 백업은 전부 일렉트론(`desktop/backup.js`)이 한다.

### 최근 접속 — 사용자 제안 (2026-08-28)

> "입구로 나가면 백엔드는 그대로 떠 있고, 최근 접속 버튼을 누르면 바로 들어가게.
> 매번 로컬 혹은 클라우드 누르고 거기서 찾아서 접속하는 게 너무 귀찮아"

맞는 지적이었다. 입구로 나가는 이유는 대부분 **DB를 갈아끼우려는 게 아니라** 설정을
보거나 잘못 들어온 것이다. 죽일 이유가 없었다.

| 상태 | [최근 접속] |
|---|---|
| 서버가 살아 있음 | **1초** — 창만 옮긴다 (실측) |
| 앱을 새로 켬 | 6~14초 — 기동은 하되 **고르는 단계를 건너뛴다** |

⚠️ **대신 새로 띄우기 전에 반드시 죽이고 기다려야 한다.** 살아 있는 놈이 `.mv.db`를 쥔 채
같은 파일을 열면 `DB_IN_USE`고, 신호만 보내고 넘어가면 잠금이 풀리기 전에 다시 열어
**간헐적으로** 실패한다 — 재현이 안 되는 부류라 처음부터 기다리게 만들었다.

### 결정

| | 무엇 | 결정 |
|---|---|---|
| ① | 백업 시점 | **열 때 자동**(내용이 바뀌었을 때만) **+ 입구에서 수동** |
| ② | 열려 있는 세이브를 백업하면 | **서버를 내리고 한다.** 안내는 안 띄운다 (사용자 결정) |
| ③ | 보존 | **30개 또는 100MB**, 최신 하나는 안 지움 |
| ④ | 되돌리기 | **새 세이브파일로.** 원본은 그대로 |
| ⑤ | 클라우드 → 로컬 | **JSON 내보내기/가져오기 재사용** |

> **③ 왜 디스크가 아니라 목록인가** — 세이브파일이 100KB 남짓이라 300개를 둬도 30MB다.
> 진짜 문제는 **되돌리려고 목록을 열었을 때 300줄이 뜨면 뭘 골라야 할지 모른다**는 것이다.
> 100MB 상한은 DB가 커졌을 때의 안전판이고, 화면이 **지금 쓰는 값과 한도를 나란히** 보여준다 —
> 안 그러면 "내 백업이 왜 없어졌지"가 된다.

> **⑤ 왜 JDBC 직접 복사가 아닌가** — §6은 "JPA를 안 거치고 JDBC로 행을 복사"라고 했다.
> 그런데 `/api/me/export`와 `import`가 **이미 있고 실데이터로 검증까지 됐다.**
> 직접 복사로 가면 identity 시퀀스 리셋과 FK 순서를 새로 짜야 하고, 이 규모에서 값을 못 한다.
> 새로 만든 것은 **빈 세이브파일에 스키마를 만드는 부분**뿐인데 그것도 백엔드를 한 번 띄우면
> Flyway가 한다.

### 🐛 밟은 것 — 가져오기가 v1.0에서 **아예 안 되고 있었다**

클라우드 뽑기가 `CONSTRAINT_VIOLATION`으로 실패했다. 원인을 파보니 뽑기 문제가 아니라
**`/api/me/import` 자체가 4단계 이후로 깨져 있었다.**

가입이 사라지면서 주인 계정을 `OwnerService`가 만드는데, 그때 `DefaultCatalogSeeder`가
기본 플랫폼(Steam·Epic…)과 입력방식을 넣는다. 즉 **가져오기가 향하는 계정은 언제나
비어 있지 않다.** 그런데 `importCatalog`가 이름이 겹쳐도 무조건 새로 만들어서
`uk_platform_member_name`에 걸렸다.

→ **이미 있으면 그 행을 다시 쓴다.** 마스터 게임을 이름으로 잇는 것과 같은 규칙이다.
회귀 테스트(`기본_선택지가_이미_있는_계정에도_들어간다`)를 붙였다.

**이게 9단계에서 드러난 게 다행이다.** 안 그랬으면 "백업 JSON이 있는데 되돌릴 수가 없다"를
정작 필요한 순간에 알았을 것이다.

## 부록 D — 실사용 피드백 반영 (2026-08-28)

앱을 직접 써보고 나온 20건. **버그 넷이 섞여 있었고 그중 둘은 심각했다.**

### 🔴 로컬 세이브파일에서 라이브러리 목록이 통째로 500이었다

```
UnconfiguredFileStorage.publicUrl() → null
  → Collectors.toMap 이 null 값에 NPE
    → GET /api/backlog 전체가 500
```

클라우드에서 뽑은 세이브파일에는 **버킷에 있던 커버**가 섞여 있는데, 로컬엔 자격증명이 없어
주소를 못 만든다. **커버 한 장 때문에 목록 전체가 죽는** 구조였다.
사이드바 이름은 `/names`라는 다른 API라 살아남고 상세는 null을 견뎌서,
겉으로는 "썸네일만 안 나온다"처럼 보였다.

### 🔴 스크린샷 업로드가 "올리지 못했습니다"만 뱉었다

스프링 기본 업로드 한도가 **파일 1MB**다. 커버 5MB·스크린샷 20MB로 정해놓고 이걸 안 올려서
**실제 스크린샷이 서버에 닿기도 전에 톰캣이 끊었다.** 게다가
`MaxUploadSizeExceededException` 핸들러가 없어 형태 없는 500이 되니 메시지도 못 갔다.

### 🐛 클라우드에서 뽑으면 게임 이름 하나가 깨졌다

```js
res.on("data", (chunk) => { body += chunk; });   // ← Buffer를 청크마다 따로 문자열로
```

한글은 3바이트라 **글자 하나가 64KB 경계에 걸치면 쪼개져 `??`가 된다.**
경계에 걸린 그 한 줄만 깨져서 원인을 찾기 어려웠다 → `res.setEncoding("utf8")`.

### 🐛 앱데이터 폴더 이름을 바꿨더니 세이브파일이 사라졌다

`starlog-desktop` → `starlog`로 바꾸면서 파일은 옮겼는데, **`settings.json`의 `dataRoot`가
옛 폴더 절대경로로 굳어 있었다.** 데이터는 새 자리에 있는데 앱은 옛 자리를 보고,
거기엔 `ensureDataRoot`가 빈 폴더를 새로 만들어 놓는다 →
**기록이 통째로 사라진 것처럼 보인다.** 이사할 때 그 값도 함께 되돌린다.

### 결정

| | 무엇 | 결정 |
|---|---|---|
| ① | 모드 이름 | **로컬 세이브파일 / 데이터베이스 연결.** 설명은 안 붙인다 |
| ② | IGDB 키 | **DB(`app_setting`)로 옮긴다.** 앱 안에서 관리·테스트 |
| ③ | 연결 저장 | **연결 테스트를 통과해야 열린다.** 값이 바뀌면 다시 닫힌다 |
| ④ | 묶음 검증 | 스토리지·IGDB는 **전부 채우거나 전부 비우거나** |
| ⑤ | 영상 | **재생·멈춤만.** mp4·mov·webm |
| ⑥ | 스크린샷 순서 | **찍은 순서** (원본 수정시각을 파일에 심는다) |
| ⑦ | 앱데이터 폴더 | `starlog` (+ 옛 폴더에서 자동 이사) |

> **② 왜 DB인가** — architecture §2의 경계표가 이미 답을 갖고 있었다.
> **"재시작이 필요한가"**가 기준인데, DB·스토리지는 부팅 때 조립되므로 일렉트론이 갖고
> **IGDB는 런타임에 바꿔도 되므로 앱 안**이다. 그런데 그 자리를 안 만들어서 키가 연결 설정에만
> 있었고, 결과적으로 **로컬 세이브파일에서는 게임 검색을 아예 못 썼다.**

> **③④ 왜 강제하나** — 아무 값이나 저장됐고, 그걸로 접속하면 **빈 화면만 하염없이** 나왔다.
> 반만 채운 것은 안 채운 것보다 나쁘다 — 조용히 실패하고 원인이 안 보인다.
> 테스트는 **DB·스토리지·IGDB를 따로** 알려준다. "연결 실패" 한 줄이면 어디가 문제인지 모른다.

> **⑥ 왜 파일 시각인가** — 서버는 파일명 순(넣은 순)으로 주는데, 옛 스크린샷 여러 장을
> 한꺼번에 끌어다 놓으면 도착 순서가 뒤죽박죽이다. 브라우저가 주는 원본 `lastModified`를
> 저장한 파일에 심으면 찍은 순서가 된다.

### 그 밖에 손본 것

**입구** — 데이터 폴더 팝업(무엇이 들어가는지·구조 생성·폴더 열기·경로 검사) ·

휴지통 · 커버 경고를 스토리지 쓸 때만

**그 밖** — 빈 커버 자리에 6초 스윕 애니메이션 · 로딩 문구 중복 제거

## 부록 E — 2차 피드백 (2026-08-28)

### 🔴 연결 테스트가 앱을 통째로 망가뜨렸다

**테스트 중에 다른 페이지로 가면 앱이 죽고, 새로고침하면 검은 화면이었다.**
IGDB 키를 지워도, 저장만 해도 같은 증상이 났다 — 원인이 하나였다.

```
connections:test
  → 본 백엔드를 죽인다 → 시험용을 띄운다 → 본 백엔드를 다시 띄운다
                                              ↑ **포트가 바뀐다**
  → 창은 옛 포트를 보고 있다 → 그 뒤 모든 요청이 TypeError: Failed to fetch
```

"여기서 고친 값은 다음에 들어올 때 적용됩니다"라고 해놓고 **사실상 재접속을 강제**한 셈이었다.

→ **본 백엔드를 아예 안 건드린다.** 죽일 이유도 없었다 — 시험 대상은 PostgreSQL이라
동시 접속이 되고, H2 파일 잠금 같은 게 없다. 다른 포트에 시험용을 하나 더 띄우고 내리면 끝이다
(`spawnProbe`). 전역 상태(`backend`·`session`·`backendPort`)를 손대지 않는 게 요점이다.

### 그 밖에

| | 무엇 | 왜 |
|---|---|---|
| 연결 테스트 진행·결과 | **버튼 옆으로** + 로딩 바 | 폼이 길어서 스크롤 안에 두면 방금 누른 것의 답이 화면 밖에 있었다 |
| 앱 안 안내 | **한 곳에** 모음 | 경고는 위, 저장 결과는 중간, 테스트 결과는 폼 안 — 흩어져서 안 보였다 |
| 일괄 동기화 | **모달로 잡아둔다** + 중단 버튼 | 다른 탭으로 가면 UI만 사라지고 동기화는 계속 돌았다 — 멈춘 줄 알고 또 누른다 |
| 세이브파일 삭제 | 확인 팝업 + **"백업도 함께 지워집니다"** | "백업이 있으니 괜찮겠지"가 이 화면에서 가장 자연스러운 오해다 |
| 백업 팝업 | 폴더 열기 추가 | 파일을 직접 옮기거나 다른 데 복사해두고 싶을 때 |
| 사용량 | 커버 `1장 · 274 KB` | 용량만으로는 몇 개인지 모른다 |
| 스윕 애니메이션 | **커버 자리 → 로딩 스켈레톤**, 6초 → 1.6초 | 커버 없는 건 로딩이 아니다 — 훑는 빛이 있으면 계속 기다리라는 뜻으로 읽힌다 |

### IGDB 키를 DB에 두는 것에 대해

물어본 김에 정리해둔다.

- **더 나빠지지 않는다.** 원래도 `connections.json`에 평문이었다 (결정 13, 명시적 결정)
- **로컬 모드**: H2 파일 = 데이터 폴더. 그 파일을 여는 사람은 이미 다 본다
- ⚠️ **클라우드 모드에서 노출면이 하나 는다** — 키가 남의 서버(Neon 등)에 올라간다.
  다만 그 서버에는 **이미 내 기록 전부**가 있고, 털렸을 때 IGDB 키로 생기는 피해는
  "남이 내 쿼터로 초당 4회를 부른다"뿐이다. 무료 API라 금전 피해가 없다
- **대안(일렉트론 설정에 두기)의 대가**: 기기를 옮길 때마다 다시 입력해야 한다 —
  §7에서 `safeStorage`를 안 쓰기로 한 것과 같은 결의 판단이다

→ **지금 구조를 유지한다.** 얻는 것(로컬 세이브파일에서 검색이 된다)이 크고,
잃는 것이 작다. 값이 커지면(유료 API 키 등) 그때 다시 본다.

## 부록 F — 3차 피드백 (2026-08-28)

### 🔴 연결 테스트가 DB 성공을 거짓으로 보고했다

**1초도 안 걸려 "DB는 됐고 나머지는 실패"가 떴다.** 원인:

```js
function waitForBackend(port) {
  if (backend === null) return reject(...);   // ← 전역 backend
```

시험용 백엔드(`spawnProbe`)는 전역에 안 들어간다. 입구 화면처럼 **본 백엔드가 없으면
그 자리에서 거부**되고, `connections:test`는 `.catch(() => null)`로 받아
`!done?.diagnostic`이 **true** — 즉 DB가 통과한 것처럼 보고했다.
→ 생사 판정을 인자로 받는다.

### 🔴 스토리지 비밀번호가 틀려도 통과했다

`/api/system`의 `configured`만 봤는데 그건 **"값이 비었나"**일 뿐이다.
자격증명이 맞는지는 스토리지에 물어봐야만 안다 →
`FileStoragePort.checkAccess()`(headBucket)를 만들고 사유를 갈라서 준다.

```
올바른 키     {"ok":true,  "message":"버킷에 접근했습니다"}
첫 글자 뺀 키  {"ok":false, "message":"액세스 키 또는 시크릿 키가 거부되었습니다"}
없는 버킷     {"ok":false, "message":"버킷을 찾을 수 없습니다: no-such-bucket-xyz"}
```

### 알림 시스템 (사용자 제안)

> "연결 테스트 해놓고 다른 페이지 갔다와도 계속 하고있고 다 되면 오는거야?
> 이걸 위한 알림 시스템 만들자"

맞는 지적이었다. 오래 걸리는 일은 **화면을 옮겨도 계속 도는데** 상태가 컴포넌트 안에 있으면
UI만 사라지고, 사용자는 **멈춘 줄 알고 또 누른다.**

- `lib/tasks.ts` — 모듈 스코프 스토어. 라우팅을 넘어 산다 (`session.ts`와 같은 방식)
- 화면 **중앙 하단**에서 올라오고 **스스로 안 사라진다.** 닫기 버튼으로만
- 담는 것은 **셋뿐** — 연결 테스트 · 일괄 동기화 · 단건 재동기화.
  아무거나 보내면 곧 토스트가 화면을 덮는다

### 연결 테스트의 입력값 규칙 (사용자 지정)

| 상황 | 어떻게 |
|---|---|
| **테스트 도는 중** 다른 화면 갔다 옴 | 입력값 **유지** |
| 테스트 안 돌리고 값만 바꾸다 나감 | **원래 값으로** |
| 손으로 새로고침 | 테스트·알림·값 **전부 초기화** |

`lib/connectionDraft.ts`가 **테스트를 시작해야만** 값을 붙든다.
그냥 만지다 나간 건 버리는 게 맞다 — "잘못 건드렸으니 나갔다 오면 되겠지"가 자연스러운
기대인데, 아무거나 붙들면 그 기대가 깨진다. 모듈 스코프라 새로고침에는 통째로 사라진다.

알림에 **[저장]**과 **[설정으로]**를 둔다 — 결과를 본 다음이 진짜 목적이라,
거기서 못 하면 "어디서 눌렀더라"를 되짚어 찾아가야 한다.

### 그 밖에

- 폼 안의 로딩바·결과 상자 제거 → **알림 한 곳에서만** 말한다
- 안내 문구와 버튼을 **한 줄로**
- 앱 설정의 IGDB 테스트도 같은 알림으로

### ⚠️ 세이브파일이 손상됐다 — 백업이 값을 했다

검증 중에 프로세스를 거칠게 정리하다 쓰기 도중에 죽였고, `EOFException`으로
파일이 안 열리게 됐다. **H2 MVStore가 크래시에 견딘다지만 절대적이지 않다.**

`04:15` 백업으로 되살려 76건을 그대로 복구했다.
다만 **자동 백업이 손상본을 그대로 복사한다** — 04:40 백업 둘은 이미 깨진 파일이었다.
보존 30개가 아니었으면 성한 것이 밀려났을 수도 있다.

### 마무리 셋 (같은 날)

**① `location.href`가 알림과 초안을 죽였다.** 알림의 [설정으로]를 누르면 문서를 통째로
다시 로드해서 **모듈 스토어가 날아갔다** — 테스트에 쓴 값이 사라져서, 테스트를 돌려놓고
자리를 뜨면 저장할 방법이 없었다. → 라우터로 옮긴다(같은 문서 안에서 화면만 바뀐다).

**② 돌아와도 첫 탭이었다.** `/system`만 기억하면 사용량 탭이 열려 연결 설정을 다시 찾아
들어가야 했다 → 주소가 탭을 정한다(`/system?tab=keys`).
초안 대조도 **바꾸기 전 이름**으로 한다 — 이름 자체를 고치는 중이면 편집한 이름으로는 안 맞는다.

**③** 연결 테스트의 `0 / 0` 숨김(몇 단계인지 모르는 일이라 개수가 뜻이 없다) ·
최근 접속의 모드 글자가 호버에서 안 바뀌던 것(`text-white/45`가 부모의 `hover:text-black`을
이겨버렸다 → 투명도만 낮춘다).

## 부록 B — 6·7·8단계 결과 (2026-08-28)

### ⚠️ 순서가 6→7→8이 아니었다

셋이 **V5 마이그레이션 하나를 공유**하는데, V5가 컬럼을 더하면서 테이블도 지운다.
**테이블을 지우려면 그걸 쓰는 코드가 먼저 없어져야 한다** — 엔티티가 살아 있는데 테이블이
사라지면 `ddl-auto: validate`가 기동을 막는다. 그래서 실제 순서는 이랬다.

```
① 8단계 앞부분 — 철거      ② V5 한 방      ③ 6단계      ④ 7단계      ⑤ 8단계 뒷부분
```

### 결정 (2026-08-28)

| | 무엇 | 결정 |
|---|---|---|
| ① | 커버·스크린샷 저장 위치 | **연결 설정의 체크박스 둘.** 체크 안 한 것은 데이터 폴더 |
| ② | API 사용량 | **호출을 행으로 남긴다.** 창(1분·1시간·24시간·30일)별로 센다 |
| ③ | 한도 표시 | **화면 상수 + 기준일 병기.** 서버가 안 준다 |
| ④ | 스크린샷 저장소 | **DB 테이블 없음.** 폴더가 곧 목록 |
| ⑤ | `/admin` | **`/system`으로 개명.** URL도 바꿨다 |

> **① 왜 자동 판정이 아니라 체크박스인가** — 처음엔 "자격증명이 있으면 스토리지"로
> 자동 판정하려 했다. 그런데 **커버와 스크린샷의 사정이 다르다.** 커버는 몇 KB지만
> 스크린샷은 장당 2~5MB에 수백 장이라 무료 티어 버킷이 먼저 찬다.
> 하나로 묶으면 **"커버만 클라우드에"가 표현이 안 된다.**
> → 체크박스 둘 + "체크 안 한 것은 이 폴더에 저장됩니다" 안내.
> **자격증명이 없으면 체크가 켜져 있어도 무시한다** (`MediaTargets`) — 올릴 데가 없는데
> 켜져 있으면 업로드가 502로 실패할 뿐이다.

> **②③ 왜 카운터가 아니라 행인가** — 예전엔 인메모리 카운터였다. 그런데 **외부 API 한도는
> "초당 4회", "월 X회"처럼 전부 기간당 횟수**라 누적 숫자 하나로는 한도에 가까운지 알 수가 없다.
> 게다가 프로세스가 죽으면 0으로 돌아가 숫자가 뜻을 잃었다.
> 행으로 남기면 어떤 창으로든 셀 수 있다. **성공·실패를 안 가린다** — IGDB 입장에서는 401도
> 이미 받은 요청이고 한도를 깎는다.
> 한도 자체는 **`lib/apiLimits.ts`가 기준일과 함께** 들고 있다 — 벤더가 언제든 바꾸고
> 우리가 조회할 방법이 없어서, 서버가 숫자를 주면 그게 조용히 거짓말이 된다.

> **④ 왜 테이블을 안 만드나** — 캡션도 순서도 안 주기로 했으니(결정 41) 저장할 게 파일 말고 없다.
> 게다가 **탐색기 열기를 주기로 한 이상 사람이 직접 지운다는 뜻**이라, 테이블을 두면
> "행은 있는데 파일이 없는" 상태를 평생 관리하게 된다. 파일이 진실이어야 앞뒤가 맞는다.

### 🐛 밟은 것 넷

**① 스크린샷 폴더가 이름이 같은 다른 게임과 겹쳤다.**
`Game.mediaFolder = slug(이름)`인데 **이름이 같은 게임이 실제로 둘 있을 수 있다** —
IGDB에서 가져온 `Hollow Knight`와 검색이 안 돼 직접 등록한 `Hollow Knight`.
그러면 두 게임의 사진이 한 폴더에 섞이고, 한쪽을 지우면 다른 쪽까지 사라진다.
→ 폴더를 정하기 전에 **다른 게임이 이미 쓰는지 확인**하고, 겹치면 게임 번호를 붙인다.

**② 테스트에서 파일은 트랜잭션 롤백을 안 탄다.**
DB는 테스트마다 되돌아가는데 디스크에 쓴 파일은 남아서, 앞 테스트의 `001.png` 때문에
다음 테스트가 `002.png`부터 시작했다. **실행할 때마다 결과가 달라졌다.**
→ `@BeforeEach`가 미디어 폴더를 직접 비운다.

**③ 프로필 파일이 테스트 설정을 덮었다** (5단계에서 배운 것의 재발).
`application-test.yml`에 스토리지 자격증명을 채워야 했다 — 안 채우면 `MediaTargets`가
"자격증명이 없으니 로컬"로 판정해 **프리사인드 3단계 테스트가 통째로 죽는다.**

**④ 로컬 파일이 `application/octet-stream`으로 나갔다.**
`<img>`는 내용을 보고 알아서 그리지만 **새 탭에서 열면 다운로드가 된다.**
→ 커버는 DB에 저장된 타입을, 스크린샷은 확장자에서 되돌린 타입을 헤더에 싣는다.

## 부록 A — 5단계 세부 계획

> 별도 문서가 아니라 여기 붙인다. 5단계가 끝나면 결과를 이 자리에 요약하고
> 세부 항목은 `v1.0-plan.md`로 옮긴다 (1·4단계와 같은 방식).

### 결정 (2026-08-27)

| | 무엇 | 결정 | 이유 |
|---|---|---|---|
| ① | 입구 화면 로드 | **`app://` 커스텀 프로토콜** (`protocol.handle`) | `file://`로 열면 Next가 뽑는 `/_next/...` **절대 경로가 전부 깨진다.** 커스텀 프로토콜은 진짜 오리진이라 그대로 돈다 |
| ② | 진단 위치 | **`main()`에서 `SpringApplication.run()` 앞, 순수 JDBC** | 스프링에 맡기면 Flyway·Hikari가 각자 다른 예외로 죽어 코드를 뽑기가 지저분하다. 별도 진단 모드는 JVM을 두 번 띄워 느리다 |
| ③ | 프로필 이름 | **`local-app` → `desktop` 개명** (6곳) | `local-app`인데 **클라우드 모드에도 붙는다.** 이름이 거짓말이 된다. 6곳뿐이라 쌀 때 고친다 |
| ④ | PG 스키마 칸 | **넣는다** (`currentSchema=`) | 한 칸이면 남의 테이블과 한 DB에서 공존해 **`DB_NOT_EMPTY`가 아예 안 생긴다** |
| ⑤ | 모드 전환 | **"입구로 돌아가기"만** | 설정에서 세이브파일 갈아끼우는 풀 UI는 9단계 |
| ⑥ | **시동 비번** | **안 한다** | 아래 |
| ⑦ | DB 비번·스토리지 키 표시 | **눈 버튼으로 보이기** | 아래 |
| ⑧ | 윈도우 | **10단계로 미룬다** | 아래 |

> **⑥ 시동 비번을 검토하고 안 하기로 했다.**
> 만들면 **암호화가 아니라 가림막**이다 — `saves/*.mv.db`도 `connections.json`도 평문이라
> 앱에 자물쇠를 달아도 파일은 그대로 열린다. 막히는 건 "옆 사람이 아이콘 눌러 구경하는 것"까지고,
> 컴퓨터를 가져간 사람이나 파일을 찾아볼 줄 아는 사람은 못 막는다.
> 진짜 암호화(H2 `CIPHER=AES`)는 **잊는 순간 데이터가 영영 안 열려서** 개인 앱에서 지불할 값이 아니다.
> → 사용자 결정: 하지 않는다.

> **⑦ 비번을 화면에 안 보내는 방어를 검토하고 접었다.**
> 처음엔 `connections.list()`에서 비번을 빼려 했는데 — **혼자 쓰는 앱에서 값을 안 하는 방어**다.
> 실제 문제는 유출이 아니라 **"오타를 확인할 수가 없다"**는 것이다.
> → `type="password"` + 눈 버튼. 저장된 값도 그대로 채운다.
> **단 java에 넘길 때는 인자가 아니라 환경변수로** 넘긴다 — `--spring.datasource.password=`는
> `ps`에 그대로 찍힌다. 위험해서가 아니라 **둘 다 한 줄이라 공짜**여서다.

> **⑧ 윈도우를 10단계로 미룬다.**
> 5단계의 윈도우 전용 사항은 **좀비 프로세스 하나**뿐이고 `stopBackend()` 함수 안에 있다.
> 구조 결정이 아니라 플랫폼 분기라 나중에 붙여도 비싸지지 않는다.
> **대신 5단계에서 지킬 것** — 경로는 전부 `path.join` · 앱데이터는 `app.getPath("userData")` ·
> `java` 실행 파일명 분기 자리를 한 곳으로 모아둔다.

### 작업 순서

#### 5-1. 일렉트론 뼈대 — 설정 파일과 IPC

```
desktop/
  main.js       app:// 등록, 입구 로드, 백엔드 관리   (개편)
  preload.js    contextBridge                        (신규)
  settings.js   settings.json / connections.json     (신규)
  paths.js      앱데이터·데이터 루트 경로              (신규)
```

`window.starlog` 표면:

| 묶음 | |
|---|---|
| 데이터 루트 | `settings.get()` · `settings.setDataRoot()` · `pickFolder()` |
| 세이브파일 | `saves.list() / create(name) / remove(name)` |
| 자격증명 | `connections.list() / save() / remove() / test()` |
| 기동 | `launch({mode, target})` · `onProgress(cb)` |

**설정 파일이 없거나 깨졌으면 안내하고 바로 기본 파일을 만든다** (architecture §5).
형식 불일치·이름 변경·삭제가 전부 같은 처리다.

#### 5-2. 스프링 진단 — 구조화된 종료

`common/diagnostic/` 신설. stdout에 한 줄 + 종료코드.

```
STARLOG_DIAGNOSTIC: DB_AUTH_FAILED
```

| SQLState / 조건 | 코드 |
|---|---|
| `08*` | `DB_UNREACHABLE` |
| `28P01` · `28000` | `DB_AUTH_FAILED` |
| `3D000` | `DB_NOT_FOUND` |
| 접속 OK + 테이블 있음 + `flyway_schema_history` 없음 | `DB_NOT_EMPTY` |
| 히스토리 최대 버전 > jar가 아는 최대 | `SCHEMA_TOO_NEW` |

스토리지(`STORAGE_AUTH_FAILED` · `STORAGE_NO_BUCKET`)는 부팅을 막지 않는다 —
`StorageConfig`가 이미 `UnconfiguredFileStorage`로 조용히 대체한다. 진단은 연결 테스트 버튼에서만.

#### 5-3. 입구 화면

`(public)/page.tsx` 개편.

- **`useSession()`을 뗀다** — 입구에는 백엔드가 없다
- IPC 유무로 분기. **개발 서버(브라우저)에는 `window.starlog`가 없어** 지금의 `[들어가기]`로 폴백
- 로컬 모드: 세이브파일 목록 (없으면 "새로 만들기")
- 클라우드 모드: 연결 목록 + 폼 (주소 · 유저 · 비번 · **스키마** / S3 4칸), 눈 버튼
- 기동 스피너 + 진단 실패 시 한글 안내

#### 5-4. H2 파일 모드
`jdbc:h2:file:<데이터루트>/saves/<이름>;MODE=PostgreSQL` · `desktop` 프로필 ·
Flyway가 파일 DB에서 V1~V4를 도는지 확인

#### 5-5. 데이터 루트
`saves/` `backups/` `covers/` `media/` 생성. 앱데이터는 저장소 밖이라 `.gitignore` 추가는 없다

#### 5-6. 프로세스 감시 + 입구로 돌아가기
백엔드가 도중에 죽으면 감지해 안내 · 백엔드 kill 후 `app://` 재로드

### ✅ 미리 짚었던 것 셋 — 전부 처리

1. **입구와 본 앱이 같은 `index.html`을 공유한다** → `AppHeader`·`ErrorNotice`의 `/`를 `/dashboard`로.

### 🐛 실제로 밟은 것 넷 — 전부 테스트로 덮음

**① 진단이 스프링과 다른 자격증명으로 H2 파일을 먼저 만들었다.**
사용자명을 안 받았을 때 빈 문자열로 접속했는데, H2는 **첫 접속이 DB를 만든다.**
그래서 새 세이브파일이 만들어지자마자 스프링이 `Wrong user name or password`로 못 열었다.
→ **주소와 사용자명이 둘 다 넘어왔을 때만 진단한다.**

**② Flyway가 만든 테이블·컬럼 이름을 못 찾았다.** 🔴 **두 번째 실행이 전부 죽던 원인**
Flyway는 H2에도 `"flyway_schema_history"`를 **따옴표 친 소문자**로 만드는데, H2는 따옴표 없는
식별자를 대문자로 올린다. 테이블은 42S02, 컬럼은 42S22(`Column "VERSION" not found`)로 죽었다.
빈 DB로 처음 뜰 때는 이력 테이블이 없어 이 코드가 안 돌아서 **첫 실행만 멀쩡했다.**
→ 테이블도 컬럼도 큰따옴표로 감싼다 (PostgreSQL도 소문자라 양쪽에서 맞는 유일한 형태).
→ 그리고 **버전 비교가 실패해도 앱을 막지 않는다** — 부가 검사가 본체를 막으면 본말전도다.
→ 테스트의 DDL도 실물처럼 따옴표를 치게 고쳤다. 안 그러면 이 버그를 영영 못 잡는다.

**③ 앱을 두 번 열면 쓸모없는 메시지가 떴다.** H2 파일 잠금(SQLState 90020)이 `DB_UNKNOWN_ERROR`로
뭉개져 "로그를 확인하세요"만 나왔다. → **`DB_IN_USE` 신설** ("이미 실행 중인지 확인해 주세요").

**④ `lastMode`를 저장할 때마다 기본 데이터 루트가 절대 경로로 굳었다.**
`patchSettings`가 **기본값이 채워진** 설정 위에 얹어서, `null`("정한 적 없음")이
"이 경로로 정함"이 됐다. → 쓰기는 원본 위에, 기본값 채우기는 읽는 쪽에서.
