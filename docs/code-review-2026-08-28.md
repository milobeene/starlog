## 🔴 앱이 죽거나 데이터에 손이 닿는 것 — 4건

### 1. 자바가 없으면 앱이 통째로 사라진다 (재현)

`main.js`의 `spawn()`에 `error` 핸들러가 없었다. `stdout`·`stderr`에만 달려 있었다.

```
Error: spawn java ENOENT
Emitted 'error' event on ChildProcess instance at:   ← 받는 이가 없다
```

Node는 받는 이 없는 `'error'`를 **던진다** → 일렉트론 메인 프로세스 즉사.
창이 안내도 로그도 없이 사라진다.

**왜 놓쳤나** — `startBackend`와 `spawnProbe`가 인자·환경변수 조립을 **두 벌** 갖고 있었다.
그래서 jar 존재 검사도 한쪽에만 있었다. 갈라진 두 벌은 반드시 어긋난다.

**고침** — `spawnJava` 하나로 합치고 `error`를 받아 `exit`과 같은 모양으로 바꿨다.
진단 코드 `JAVA_NOT_FOUND`·`JAR_MISSING`을 만들어 한글 안내가 나가게 했다.

> ⚠️ **10단계에서 JRE를 번들해도 이 방어는 필요하다.** 번들 경로가 틀리면 똑같이 ENOENT다.

### 2. 백엔드가 JSON이 아닌 걸 주면 메인 프로세스가 죽는다 (재현)

`getJson`·`postJson`의 `JSON.parse`가 `res.on("end")` 콜백 **안**에 있었다.
그 콜백은 Promise 실행자가 끝난 뒤 다음 틱에서 도므로, 거기서 던진 예외는
`reject`로 안 가고 **처리되지 않은 예외**가 된다.

```
SyntaxError: Unexpected token '<', "<html>not "... is not valid JSON
    at IncomingMessage.<anonymous>       ← Promise 밖
```

스프링이 200에 HTML 에러 페이지를 주는 순간 앱이 죽는다. `getJson`은 `/api/me/export`,
`postJson`은 `/api/me/import`에 쓰이므로 **뽑기 도중이면 반쯤 만들어진 세이브파일이 남는다.**

**고침** — `parseInto`로 빼서 `try`로 감쌌다.

### 3. 같은 백업을 두 번 되돌리면 못 여는 세이브파일이 생긴다 (재현)

이름을 **만드는 쪽**(`backup.js`)과 **검사하는 쪽**(`main.js`)이 서로를 몰랐다.

```
✅ 열림   내 기록 2026-08-28_053012
❌ 못엶   내 기록 2026-08-28_053012 (2)      ← 괄호가 허용 문자에 없다
```

`saves:remove`도 같은 검사를 지나므로 **열 수도 지울 수도 없다.** 탐색기로 직접
지우는 수밖에 없었다. 세이브 이름이 33자를 넘으면 `(2)` 없이도 첫 되돌리기부터 그랬다.

**고침** — 규칙을 `desktop/saveName.js`로 뽑아 양쪽이 같은 상수를 보게 했다.
사람이 입력한 이름은 `assertSaveName`이 **거절**하고, 우리가 조립한 이름은 `fit`이 **다듬는다**.
꼬리(`-2`)의 자리를 먼저 떼어두고 앞을 줄이므로 충돌 회피가 잘려나가지 않는다.

### 4. 클라우드→세이브파일 뽑기 뒤 창이 죽은 포트를 본다

`cloud:toSaveFile`이 본 백엔드를 죽이고 → 로컬을 띄워 부어넣고 → **새 포트로** 클라우드를
되살렸는데, **창을 옮기는 줄이 없었다.** 이 기능은 앱 안(`/settings`)에서 부르므로
성공하는 그 순간부터 앱 전체가 `Failed to fetch`가 된다.

**연결 테스트에서 이미 고쳤던 것과 똑같은 실수다.** `void cloudPort;`라는 줄이 남아 있어
원래 쓰려다 만 흔적이 보였다.

**고침** — 죽일 이유가 애초에 없었다. 상대는 **다른 DB의 다른 포트**다.
시험용(`spawnProbe`)과 같은 방식으로 격리해 띄우고 내린다 — 창도 세션도 그대로다.
실패하면 반쯤 만들어진 세이브파일도 치운다(안 치우면 같은 이름으로 재시도할 수 없다).

## ⚪ 정리 — 10건

- **`frontend/next.config.ts.bak`이 커밋돼 있었다.** `git rm` + `.gitignore`에 `*.bak`·`*.orig`·`*.rej`
- `stopBackend`의 5초 SIGKILL 타이머를 안 지워 **이미 죽은 pid에** 신호를 쐈다
- `app.on("before-quit", stopBackend)` — **일렉트론은 Promise를 안 기다린다.** 신호만 보내고
  즉시 끝나서 H2가 잠금을 놓기 전에 사라졌다 → **끄고 바로 켜면 `DB_IN_USE`.**
  `preventDefault` 후 기다렸다 스스로 `quit()`. `process.on("exit")`은 동기 신호만 보내는
  최후 방어선으로 남겼다(크래시·Ctrl+C)
- `getSettings`의 병합이 **한 겹**이라 `settings.json`에 `"window": null`이 있으면
  `createWindow`가 죽었다 — **창이 안 뜨는데 오류도 안 보이는** 상태. 폴더 열기를 주는 이상
  사람이 파일을 건드릴 수 있다
- `ScreenshotService.delete`가 요청 개수를 그대로 반환했다. 삭제가 실패를 삼키므로
  **한 장도 못 지우고 "3장 삭제"**가 가능했다 → 실제로 지운 것만 센다
- `preload.js`의 `backToEntry` 주석이 "백엔드를 죽이고"라고 했다 — 9단계에 안 죽이게 바뀌었다
- `tasks.ts`의 `putTask` 주석("같은 종류는 하나만")과 코드(`id`로 거름)가 안 맞았다
- `importCatalog`이 `DefaultCatalogSeeder`와 **짝을 맞춰야 한다는 사실이 어디에도 없었다.**
  시드에 한 종류만 더 넣으면 가져오기가 통째로 실패한다 — 실제로 그렇게 났고 한동안 아무도 몰랐다.
  코드는 지금 맞으므로 **경고 주석만** 남겼다
- eslint 미사용 변수 2건 제거 (9 → 7 warnings)
- 세이브 이름에서 **윈도우 예약어**(`CON`·`NUL`·`PRN`·`COM1`…)와 끝의 공백·점을 막았다.
  맥에서는 아무 문제 없이 만들어져서 **윈도우에서만 터질** 부류다 (10단계 대비)
