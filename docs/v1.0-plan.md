## 1. 좋은 소식 — 이미 준비돼 있던 것들

### 1-1. 인증 제거의 이음매가 파일 하나다

`@LoginMember`를 쓰는 컨트롤러가 18개인데 값은 전부
[`LoginMemberArgumentResolver`](../backend/src/main/java/com/milobeene/starlog/common/web/LoginMemberArgumentResolver.java)
한 곳을 통과한다. `SecurityContext`에서 `MemberPrincipal`을 꺼내는 게 전부다.

**이 클래스만 고치면 컨트롤러 18개가 그대로 산다.** Spring Security를 뜯을 이유가 없다 —
뜯으면 오히려 수십 곳을 고쳐야 한다. I-3에서 헤더 인증 → 시큐리티 컨텍스트로 갈아탈 때도
컨트롤러 시그니처가 하나도 안 바뀌었다. **그러려고 리졸버로 감쌌던 것이다.**

### 1-2. 포트가 이미 세 군데 뚫려 있다

| 포트 | 지금 | v1.0 |
|---|---|---|
| `FileStoragePort` | R2 (S3 호환) | **S3 호환 아무거나 + DB 저장 구현체 추가** |
| `GameCatalogClient` | IGDB HTTP | 그대로 (키는 사용자 것) |
| `AuthMailSender` | Resend / 로깅 | 폐기 |

`StorageConfig`가 자격증명이 없으면 `UnconfiguredFileStorage`로 조용히 대체한다 —
**설정 없이도 앱이 뜨는 길이 이미 있다.**

### 1-3. 마이그레이션이 이미 이식 가능하다 (2026-08-27 실측)

- V1~V3에 **PostgreSQL 전용 문법 0건** (`jsonb`·`serial`·`::`·`on conflict`·`create extension`)
- 타입은 `bigint`/`timestamp`/`date`/`integer`/`text`/`boolean`/`bytea`만
- ID 전략 17개 전부 `bigint generated by default as identity` — **SQL 표준**
- **H2·PostgreSQL 드라이버가 이미 둘 다 클래스패스에** 있고 프로필이 URL로 가른다

→ **로컬 모드가 현실적이라는 근거가 여기서 나왔다.** 이게 아니었으면 마이그레이션을
두 벌로 갈라야 했다.

### 1-4. 스토리지가 이미 S3 호환 추상이다

`S3CompatibleFileStorage` + `endpointOverride` → AWS S3 · R2 · MinIO · B2 · Wasabi 전부.
`build.gradle` 주석에 "나중에 S3·MinIO로 옮겨도 엔드포인트 설정만 바뀐다"고 적혀 있다.

### 1-5. IGDB 없는 경로가 이미 화면까지 붙어 있다 ✅ 확인됨

`add/page.tsx`에 **"직접 등록" 버튼**이 있고, `GameService`가 `Game.manual(name)`으로
**마스터까지 만든다.** IGDB 키가 없어도 앱이 온전히 쓸모 있다.

### 1-7. 마스터 재동기화가 이미 있다 ✅

`GameResyncService` + `POST /api/admin/games/{gameId}/resync`.
**일괄 동기화는 이걸 1초 간격으로 도는 루프**라서 새로 짤 로직이 거의 없다.

### 1-8. `Game.lastSyncedAt`이 이미 있다 ✅

그래서 일괄 동기화의 **진행 상태를 저장할 곳이 필요 없다** —
"3개월 지난 게임 수"를 세면 진행률이 나온다 (`architecture.md` §10-2).

### 1-6. 프론트가 전부 클라이언트 컴포넌트다

`page.tsx` 전부가 `"use client"`. 서버 컴포넌트는 레이아웃 셸 셋과 `not-found.tsx`뿐이고
전부 정적이다. **서버 렌더링에 기대는 로직이 없다.**

## 2. 함정 — 밟을 것들

### 2-1. 🔴 스프링은 DB를 모르는 채로 못 뜬다

→ **`v1.0-architecture.md` §2에서 "백엔드 늦게 띄우기"로 해결.**
이 문서에서 가장 중요한 항목이었고 이미 결론이 났다.

### 2-2. ~~`NEXT_PUBLIC_API_BASE`가 빌드 시점에 굳는다~~ ✅ 해결됨

```
frontend/src/lib/api.ts:10
frontend/src/components/auth/AuthCard.tsx:50
frontend/src/app/(app)/settings/page.tsx:436
```

백엔드를 늦게 띄우면 포트를 실행 시점에 고르므로 빌드 때 알 수 없다.
→ 일렉트론 preload가 런타임 주입하거나, 스프링이 서빙해서 상대 경로만 쓰거나.
**입구 화면은 어차피 `file://`이라 별도 취급이 필요하다.**

### 2-3. ~~`/library/[entryId]`가 정적 내보내기를 막는다~~ ✅ 해결됨 — 쿼리로 옮김

`output: 'export'`는 동적 경로에 `generateStaticParams`를 요구하는데 entryId는
빌드 시점에 알 수 없다. → 스프링이 SPA 폴백으로 서빙하면 해결.

### 2-4. R2 CORS에 일렉트론 오리진이 없다

지금 버킷 CORS는 `https://starlog-xi.vercel.app`과 `http://localhost:3000`만 허용한다.
**프리사인드 PUT이 프리플라이트에서 막힌다.**
→ 각 사용자가 자기 버킷 CORS를 설정해야 한다. **안내 문서가 필요하다.**
(로컬 폴더 저장을 쓰면 이 문제 자체가 없다)

### 2-5. 커버 업로드 경로가 두 갈래가 된다

프리사인드(S3) vs 백엔드 통과(DB). 백엔드 엔드포인트 신설 + 프론트 분기 + 내려주는 경로 분기.
→ `architecture.md` §4. **과소평가하기 쉬운 실제 일거리다.**

### 2-6. JRE는 플랫폼별이다 → 윈도우 빌드는 윈도우에서

번들 JRE든 jlink든 OS·아키텍처별 산출물이다. 맥에서 윈도우용 크로스 빌드는 고생길이다.

### 2-7. Neon 오토서스펜드 + 커넥션 풀

Neon은 놀면 컴퓨트를 재운다. 앱을 켜둔 채 자리를 비우면 풀 안 커넥션이 죽어 있다.
→ 풀 크기 2, idle timeout 짧게, **borrow 시 검증** 켜기. 깨우는 1초는 감수.

### 2-8. 쓰는 중인 H2 파일을 `cp`로 복사하면 손상된다

→ H2 `BACKUP TO` 사용. `architecture.md` §5.

### 2-9. 좀비 스프링 프로세스 — 맥에서는 ✅ 확인됨, 윈도우는 아직

`before-quit`에서 SIGTERM → 3초 뒤 SIGKILL. **맥에서는 일렉트론만 죽여도 java가 같이 죽는다.**
윈도우는 신호 체계가 달라 `taskkill /T`가 필요할 수 있다 — 5단계에서 확인할 것.

### 2-10. ~~정렬 콜레이션~~ ✅ 해결됨

H2와 PostgreSQL이 이름순을 다르게 정렬하는 문제였다.
**정렬 키 칸을 두고 앱이 계산하기로 하면서 DB에 의존하지 않게 됐다**
(`architecture.md` §10-5). Neon 콜레이션을 확인할 필요도 사라졌다.

### 2-11. 커버 업로드 다이얼로그에 실제 버그가 있다 🐛

`CoverDialog`에 **드래그 앤 드롭이 아예 없고** `<input type="file">` 하나뿐이다.
그런데 박스를 넓게 스타일링해둬서 **아무 데나 눌러도 될 것 같지만 왼쪽 작은 버튼만 동작한다.**
(드롭이 되는 것처럼 보였던 건 브라우저가 파일 input에 기본 제공하는 동작이다)

→ 커버·스크린샷 둘 다 새로 만든다 (`architecture.md` §10-1).

### 2-12. 시드에 개인 데이터가 있다 ⚠️

`DataInitializer`가 넣는 것이 **내 하드웨어 목록과 내 게임 기록**이다.
지금은 `@Profile("dev")`가 막고 있다 — **이 조건을 푸는 순간 배포에 섞인다.**
→ ~~`v1.0-decisions.md` N1 (보류)~~ **✅ 닫힘 (결정 66)** — 5단계에서 실사용 프로필(`desktop`)이
생기면 `DataInitializer`가 아예 안 돈다. 빈 DB에 들어가는 것은 `OwnerService`의 주인 계정과
`DefaultCatalogSeeder`의 기본 플랫폼·입력방식뿐이다. **"정할 것"이 아니라 "5단계가 처리하는 것"이었다.**

## 4. 완료된 것

### ✅ 6·7·8단계 — 미디어와 정리 (2026-08-28)

**상세는 `v1.0-roadmap.md` 부록 B.** 여기는 함정만 남긴다.

1. 🔴 **순서가 6→7→8이 아니다.** V5가 컬럼을 더하면서 테이블도 지우는데,
   **테이블을 지우려면 그 코드가 먼저 없어져야 한다** (`ddl-auto: validate`가 기동을 막는다)
2. **같은 이름의 게임이 둘 있을 수 있다** — IGDB판과 직접등록판. slug 폴더가 겹쳐서
   두 게임의 스크린샷이 한 폴더에 섞였다
3. **테스트에서 파일은 롤백을 안 탄다.** DB는 되돌아가는데 디스크는 남아서
   실행할 때마다 결과가 달라졌다 → `@BeforeEach`가 폴더를 비운다
4. **`application-test.yml`에 스토리지 자격증명을 채워야 한다** — 안 채우면
   `MediaTargets`가 "로컬"로 판정해 프리사인드 테스트가 통째로 죽는다
5. **로컬 파일은 Content-Type을 직접 실어야 한다.** 안 하면 `<img>`는 그려도
   새 탭에서 열면 다운로드가 된다
6. `GID`는 **zsh 예약 변수**다 — 셸 검증 스크립트에서 쓰면 "failed to change group ID"가 난다

### ✅ 5단계 — 입구 화면 + 로컬 모드 (2026-08-28)

**상세는 `v1.0-roadmap.md` 부록 A.** 여기는 함정만 남긴다.

1. 🔴 **Flyway 이력 테이블은 H2에서 따옴표 친 소문자다.** 안 감싸고 조회하면 42S02/42S22.
   **빈 DB로 처음 뜰 때는 이력 테이블이 없어 이 코드가 안 돌아서 첫 실행만 멀쩡했다** —
   두 번째 실행부터 전부 죽는 종류다
2. **H2는 첫 접속이 DB를 만든다.** 진단이 스프링과 다른 자격증명으로 붙으면
   새 세이브파일이 만들어지자마자 못 쓰게 된다
3. **부가 검사가 본체를 막으면 안 된다.** 버전 비교가 실패했다고 정상 세이브파일을 못 열면 본말전도
4. **프로필 파일은 활성 순서대로 쌓인다.** `application-desktop.yml`에 `ddl-auto`를 중복해 적었더니
   `desktop`+`test`로 도는 테스트의 컨텍스트가 통째로 안 떴다 → **다른 값만 적는다**
5. **일렉트론 창은 CDP로 조작할 수 있다** (`--remote-debugging-port`). 창을 볼 수 없을 때
   흐름을 끝까지 태우는 유일한 방법이었다

### ✅ 4단계 — 인증 제거 (2026-08-27)

**로그인이 없다. 앱을 열면 바로 내 기록이다.**

| 지운 것 | |
|---|---|
| `auth/` | 36파일 1,861줄 |
| 테스트 | `auth/` 11파일 + e2e + 인가 테스트 13개 |
| 프론트 화면 | login · signup · password-reset×2 · verify-email · restore |
| 설정 | `SecurityConfig` · `CorsConfig` · `SessionConfig` · `DevAuthConfig` · `AdminBootstrap` |
| 의존성 | security · oauth2-client · session-jdbc · resend · security-test |
| 화면 | 설정의 `계정` 섹션 통째로 (이메일 변경·비밀번호·구글 연결·회원 탈퇴) |

**jar 86MB → 74MB.**

#### 이음매는 파일 하나였다

`LoginMemberArgumentResolver` 한 곳만 바꿔 **컨트롤러 18개가 한 줄도 안 바뀌었다.**
값은 `OwnerService.ownerId()`가 준다 — 회원이 없으면 만들고, 있으면 가장 먼저 만들어진 것.

⚠️ **`DefaultCatalogSeeder`가 갈 곳을 잃을 뻔했다.** 기본 플랫폼·입력방식 시드는
**가입할 때** 돌았는데 가입이 사라졌다. `OwnerService`가 받는다 — 안 그러면 빈 목록으로 시작한다.

#### 밟은 것 셋

1. **`AfterCommit`이 `auth/`에 있었다.** 커버 삭제(R2)가 쓰는 범용 도구인데 인증 메일이
   첫 사용처라 거기 있었다. 삭제가 아니라 `common/util/`로 **이동**해야 했다
2. **`MemberPurgeService`가 `AuthToken`을 지우려 했다.** 엔티티가 사라져
   `UnknownEntityException`으로 **회원 물리 삭제가 통째로 깨졌다.**
   어젯밤 만든 `MemberPurgeSchemaTest`가 잡았다 — 그 테스트를 만든 이유가 정확히 이거다
3. **개발 서버가 CORS로 막혔다.** `:3000 → :8080`이 교차 오리진인데 `CorsConfig`를 지웠다.
   설정을 되살리는 대신 **Next 개발 서버가 `/api`를 프록시**하게 했다 —
   실사용(스프링이 프론트까지 서빙)과 같은 "오리진 하나" 구조가 개발에도 적용된다

#### 테스트 헤더는 남겼다 (인증이 아니다)

컨트롤러 테스트 16파일 208줄이 `X-Member-Id`로 **특정 회원인 척**하며 돈다.
무조건 주인 id를 주면 소유권 테스트가 전부 무의미해지고,
`member.id.eq(memberId)`를 빠뜨리는 실수를 잡던 그물이 사라진다.
→ `MemberIdOverride`를 **dev·test 프로필에서만** 빈으로 올린다. 실사용 빌드엔 그 코드가 없다.

#### 임시 상태 — 5단계가 갈아끼울 자리

**입구(`/`)에 `[들어가기]` 버튼 하나만 있다.** 여기가 **모드 선택**
(`[로컬 모드]` / `[클라우드 모드]`) 자리다 — architecture §2, 결정 40.
5단계에서 일렉트론이 `app://`로 직접 로드하는 화면이 된다.

### ✅ 1단계 — 일렉트론 껍데기 (2026-08-27)

**"창 안에서 STARLOG가 뜬다"까지 확인했다.** 인증은 아직 그대로 살아 있다.

- `desktop/main.js` — 빈 포트 선택 → java spawn(인자 주입) → HTTP 대기 → 창 로드 → 종료 시 정리
- `tools/build-desktop.sh` — 프론트 정적 빌드 → 백엔드 리소스 복사 → `bootJar` (86MB)
- `StaticSiteConfig` — 스프링이 프론트 서빙. `/dashboard` → `dashboard.html`
- 검증표는 `v1.0-architecture.md` §2. **좀비 프로세스 없음까지 확인.**

**아직 안 한 것**: 입구 화면(모드 선택·키 입력)이 없어서 설정을 상수로 넘긴다.
그래서 지금은 개발과 같은 대상(Neon)을 본다. 인증도 살아 있어 로그인 화면을 거친다.

### ✅ 플레이 시간 소수점 + 캘린더 임포트 (2026-08-27)

## 5. 그 밖에 눈에 띈 것

- **`LICENSE` 파일이 없다.** 남에게 줄 거면 필요하다

  일렉트론에서는 앱을 열 때마다 돈다. 소유자 memberId 생성을 여기 얹는다
- **알려진 한계 3건**(재발송 스로틀 레이스 / 플랫폼 삭제 경합 / 병합 레이스)은
