# v1.0 — 일렉트론 데스크탑 앱 계획

> 2026-08-27 작성. v0.1(웹) 완료 직후, 코드베이스 전수 조사 결과.
>
> **모든 게 정해지지 않았다.** 결정이 필요한 것은 `docs/v1.0-decisions.md`에 따로 모아뒀다.
> 이 문서는 **조사 결과와 선택지**다 — 정해진 것만 확정으로 적었다.

## 0. 확정된 전제 (2026-08-26 밤 대화)

| | |
|---|---|
| **죽는 것** | Render · Vercel |
| **사는 것** | **Neon · R2 · IGDB** — 그대로 라이브로 쓴다 |
| **사용자** | 나 혼자. **윈도우 PC + 맥북 두 대.** 폰은 안 씀 |
| **자격증명** | 앱이 들고 있는다 (단, 번들이 아니라 번들 **옆**) |
| **배포** | 안 뿌린다. 혹시 달라는 사람이 있으면 저장소를 준다 |

**왜 Neon을 남기나** — 기기가 둘이라서다. 로컬 파일이면 윈도우와 맥북 사이에서 백업을
주고받아야 하는데, DB 파일은 클라우드 동기화 폴더에 두면 **충돌이 아니라 손상**이 난다
(파일을 열어둔 채 조금씩 쓰고, 락 파일·트랜잭션 로그가 본 파일과 짝을 이뤄야 한다).
Neon을 남기면 그 문제가 **생기지도 않는다.**

**대가 하나** — 지연이 옮겨간다. 지금은 Render(싱가포르)와 Neon(싱가포르)이 같은 곳이라
DB 쿼리가 1~5ms이고 느린 건 브라우저→서버 한 홉(130ms)뿐이다. 앱을 내 컴퓨터로 옮기면
**API 호출이 공짜가 되는 대신 쿼리 하나하나가 한국↔싱가포르 80ms**가 된다.
Neon은 서울·도쿄 리전이 없어 싱가포르가 최선이다.
→ **따뜻할 때 체감은 지금과 비슷하거나 조금 나쁠 수 있다. 진짜 이득은 50초 콜드스타트가
사라지는 것이고, 그게 애초에 데스크탑으로 가려던 이유다.**

## 1. 코드베이스 조사 — 좋은 소식

### 1-1. 인증 제거의 이음매가 **파일 하나**다

`@LoginMember`를 쓰는 컨트롤러가 18개인데, 값은 전부
[`LoginMemberArgumentResolver`](../backend/src/main/java/com/milobeene/starlog/common/web/LoginMemberArgumentResolver.java)
한 곳을 통과한다. `SecurityContext`에서 `MemberPrincipal`을 꺼내는 게 전부다.

**이 클래스만 고치면 컨트롤러 18개가 그대로 산다.** Spring Security를 뜯을 이유가 없다 —
뜯으면 오히려 수십 곳을 고쳐야 한다. 실제로 I-3에서 헤더 인증 → 시큐리티 컨텍스트로
갈아탈 때도 컨트롤러 시그니처가 하나도 안 바뀌었다. **그러려고 리졸버로 감쌌던 것이다.**

### 1-2. 포트가 이미 세 군데 뚫려 있다

| 포트 | 지금 구현 | v1.0에서 |
|---|---|---|
| `FileStoragePort` | R2 (S3 호환) | **그대로.** 로컬 폴더로 갈 일이 없어졌다 |
| `GameCatalogClient` | IGDB HTTP | 그대로 |
| `AuthMailSender` | Resend / 로깅 | 폐기 |

`StorageConfig`가 자격증명이 없으면 `UnconfiguredFileStorage`로 조용히 대체한다 —
설정 파일이 없어도 앱이 뜨고 업로드만 실패한다. **첫 실행 경험이 이미 안전하다.**

### 1-3. 프론트가 전부 클라이언트 컴포넌트다

`page.tsx` 전부가 `"use client"`다. 서버 컴포넌트는 레이아웃 셸 셋(`layout.tsx`,
`(public)/layout.tsx`, `(app)/library/layout.tsx`)과 `not-found.tsx`뿐이고 전부 정적이다.

**서버 렌더링에 기대는 로직이 없다** → 일렉트론이 파일로 서빙하는 길이 열려 있다.
(단, 아래 2-3의 함정이 있다)

## 2. 조사 — 걸리는 것 (전환 블로커)

### 2-1. `NEXT_PUBLIC_API_BASE`가 **빌드 시점에 굳는다** ⚠️

```
frontend/src/lib/api.ts:10   const BASE = process.env.NEXT_PUBLIC_API_BASE ?? "http://localhost:8080";
frontend/src/components/auth/AuthCard.tsx:50
frontend/src/app/(app)/settings/page.tsx:436
```

일렉트론은 보통 **빈 포트를 실행 시점에 골라** 백엔드를 띄운다(포트 충돌 회피).
그러면 프론트가 빌드할 때 그 포트를 알 수 없다.

**선택지 셋**
- ⓐ **포트를 고정한다** — 가장 쉽다. 충돌하면 앱이 안 뜬다
- ⓑ **런타임 주입** — 일렉트론 preload가 `window.__STARLOG_API__`를 심고 `api.ts`가 그걸 먼저 본다
- ⓒ **같은 오리진으로 합친다** — Spring이 프론트 정적 파일까지 서빙. 상대 경로만 쓰면 되고
  **CORS·CSRF·쿠키 문제가 통째로 사라진다.** 대신 2-3을 먼저 풀어야 한다

→ `decisions.md` Q2

### 2-2. R2 CORS에 일렉트론 오리진이 없다 ⚠️

커버 업로드는 브라우저가 R2로 **직접 PUT**한다. 지금 버킷 CORS는
`https://starlog-xi.vercel.app`과 `http://localhost:3000`만 허용한다.
일렉트론 렌더러 오리진은 여기 없다 → **업로드가 프리플라이트에서 막힌다.**

**선택지**
- 일렉트론이 쓰는 오리진을 CORS에 추가 (ⓐ/ⓑ면 `http://localhost:고정포트`)
- ⓒ로 가면 백엔드와 같은 오리진이라 **CORS 자체가 필요 없어진다**

### 2-3. `/library/[entryId]`가 정적 내보내기를 막는다 ⚠️

`output: 'export'`는 동적 경로에 `generateStaticParams`를 요구하는데, entryId는
빌드 시점에 알 수 없다.

**선택지 셋**
- ⓐ **경로를 쿼리로 바꾼다** — `/library?entry=5`. 화면 하나만 고치면 되지만 URL 모양이 바뀐다
- ⓑ **일렉트론 안에서 Next 서버를 띄운다** — 일렉트론에 Node가 있으니 가능하다. 프로세스가 하나 더 늘고 기동이 느려진다
- ⓒ **Spring이 SPA 폴백으로 서빙** — 모르는 경로를 전부 `index.html`로 넘긴다. 클라이언트 라우팅이라 동작하고, 2-1ⓒ와 자연스럽게 붙는다

→ `decisions.md` Q2와 한 묶음이다

### 2-4. 세션 쿠키가 `Secure` + `SameSite=None`이다

`application-prod.yml`이 크로스 도메인용으로 그렇게 잡아뒀다. 일렉트론에서는
오리진이 하나라 이 설정이 오히려 방해가 된다.
**인증을 없애기로 하면 이 항목은 통째로 사라진다** (Q1).

### 2-5. 구글 OAuth 리다이렉트 URI가 통째로 바뀐다

지금은 서버 리다이렉트 흐름이다. 데스크탑은 `http://127.0.0.1:<임의포트>` **루프백 흐름**이라
`GoogleOAuth2SuccessHandler`·`OAuthRedirects` 계열을 새로 짜야 한다.
**인증을 없애면 이것도 사라진다** (Q1).

### 2-6. JRE는 플랫폼별이다 → **윈도우 빌드는 윈도우에서**

번들 JRE든 jlink든 OS·아키텍처별 산출물이다. 맥에서 윈도우용을 크로스 빌드하는 건
현실적으로 고생길이다. **두 기계에서 각각 빌드**하는 게 정직하다.

### 2-7. 마이그레이션 주인이 사라진다 ⚠️

Render가 죽으면 Flyway를 누가 올리나. 기계가 둘이라 **버전이 어긋나면 앱이 안 뜬다** —
맥북이 V4를 올렸는데 윈도우가 옛 빌드면 Hibernate `validate`가 실패한다.

기계가 둘뿐이라 "스키마 바꾸면 양쪽 다 다시 빌드"로 충분하지만,
**실패했을 때 메시지가 읽혀야 한다.** 스택트레이스만 보고 한참 헤매게 된다.

### 2-8. Neon 오토서스펜드 + 커넥션 풀

Neon은 놀면 컴퓨트를 재운다(무료 100 CU-시간을 지키는 방법이기도 하다).
앱을 켜둔 채 자리를 비우면 풀 안의 커넥션이 죽어 있다.
→ 풀 크기 2, idle timeout 짧게, **borrow 시 검증** 켜기. 깨우는 1초는 감수.

### 2-9. `logout()`이 `window.location.href = "/"`를 쓴다

일렉트론에서 오리진 구성에 따라 깨질 수 있다. **인증을 없애면 사라진다.**

## 5. 작업 순서 (초안)

**원칙: 중간에 앱이 깨지지 않게.** 각 단계 끝에서 웹이 여전히 돌아야 한다.

```
0. 안전망      ✅ 2026-08-27 완료 — GET /api/me/export, POST /api/me/import
1. 껍데기      일렉트론 + 번들 백엔드 + 프론트 서빙. 기존 인증 그대로 두고 뜨는 것만 확인
2. 인증 제거   LoginMemberArgumentResolver 한 곳. 여기서 (public)/ 화면이 무의미해진다
3. 정리        auth·admin·quota 제거 또는 비활성 (Q4)
4. 설정 외부화 자격증명을 번들 밖 config로. Neon 앱 전용 역할 + R2 스코프 토큰
5. 두 번째 기계 윈도우에서 빌드·기동 확인
6. 웹 내리기   Render·Vercel 중단 (Q6 — 언제)
```

**0번이 왜 먼저였나** — 76건 + 회차·취득·메모가 **Neon에만 있었다.** 무료 프로젝트는
오래 안 쓰면 정지될 수 있고, 앞으로 스키마를 만질 일이 많다.
**내보내기는 백업이자 이사 수단이자 앞으로도 계속 쓸 안전망이다.**

### 0번 결과 (2026-08-27)

- `GET /api/me/export` — JSON 한 벌. 자격증명은 안 담긴다
- `POST /api/me/import` — **빈 계정에만**. 병합은 409로 거부
- 실데이터 검증: 항목 76 / 회차 64 / 취득 76 / 메모 43 / 지출 1,885,530원 — 원본과 일치
- 파일: `backups/starlog-export-*.json` (gitignore됨)

**⚠️ 커버는 `storageKey`만 담는다.** 실물은 R2에 있다 — R2를 남기기로 했으니 성립한다.
**R2까지 버리면 이 키는 무용지물**이 되고, 그때는 이미지 바이너리 내보내기가 따로 필요하다.

**왕복 테스트가 핵심이다.** 내보낸 걸 다시 넣었을 때 같은 것이 안 나오면 백업이 아니라
그냥 파일이다. `status`·`displayName`·`lastPlaythrough`는 담지 않고 가져오기가 다시 계산하므로,
거기가 깨지면 전 항목이 위시리스트에 이름 없이 복원된다 — 테스트가 그걸 지킨다.

## 6. 그 밖에 눈에 띈 것

- **`LICENSE` 파일이 없다.** 저장소를 남에게 준다면 필요하다
- `build.gradle`의 `version = '0.0.1-SNAPSHOT'`이 한 번도 안 올라갔다. `bootJar` 이름을
  `app.jar`로 고정한 건 Render 시작 명령 때문인데, **Render가 죽으면 그 제약이 사라진다**
- `SPRING_SESSION` 테이블(V2)은 세션을 없애면 남는 유령이 된다. V4에서 정리할지 판단 필요
- `AdminBootstrap`·`DataInitializer`가 `ApplicationRunner`다. 일렉트론에서는 앱을 열 때마다 돈다
- `StartupCleanup`(2026-08-26 추가)도 마찬가지 — 의도한 동작이지만 인증을 없애면
  탈퇴 유예 정리는 무의미해진다
- **알려진 한계 3건**(재발송 스로틀 레이스 / 플랫폼 삭제 경합 / 병합 레이스)은
  전부 `auth`·다인 전제라 **v1.0에서 자연 소멸**한다
