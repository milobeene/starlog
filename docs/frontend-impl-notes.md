# 프론트엔드 구현 메모 (Phase 8)

**구현할 때 보는 문서다.** 화면별로 어떤 API를 타는지, 어디가 함정인지.
디자인용 화면 구성은 `frontend-brief.md`, API 세부는 `api-design-v0.2.md`, 판단 기준은 `spec-v1.5.md`.

---

## 0. 현재 상태

목업(5,239줄)을 전부 걷어내고 **라우트 껍데기만** 남겼다. 남은 것은 두 개뿐이다.

| 파일 | 왜 남겼나 |
|---|---|
| `src/lib/types.ts` | 백엔드 DTO 미러. 디자인과 무관하게 맞다 |
| `src/lib/labels.ts` | enum → 한국어 라벨 + 포매터 (`formatRating`, `formatMoney`) |

`globals.css`는 리셋만 남았다. **색·간격·타이포 토큰은 비어 있고, 디자인이 채운다.**

### 확정한 구조 결정

1. **정적 export를 쓰지 않는다.** 세션 쿠키가 브라우저에 있고 백엔드가 다른 도메인이라
   서버 컴포넌트에서 부르면 쿠키를 수동 포워딩해야 한다. 이득이 없다.
   → **데이터 페칭은 전부 클라이언트.** 대신 `[entryId]` 동적 라우트가 자유롭다.
2. **라우트 그룹으로 껍데기를 가른다.** `(public)`은 메뉴가 없고, `(app)`에만 헤더가 있다.
3. **상세를 별도 라우트로 뺀다.** 뒤로가기·새로고침·링크 공유가 공짜다.
4. **프로필과 설정을 `/settings` 하나로 합친다** (스펙 §13 "화면 4개"와 일치).

## 1. 라우트

```
(public)  메뉴 없음
  /                          랜딩
  /login                     로그인
  /signup                    회원가입
  /verify-email?token=       이메일 인증
  /password-reset            재설정 요청
  /password-reset/confirm?token=   새 비밀번호
  /restore                   탈퇴 유예 복구

(app)  헤더 있음 · 인증 필요
  /dashboard                 대시보드
  /library                   목록
  /library/[entryId]         상세/편집
  /add                       담기
  /settings                  프로필 · 계정 · 사전
  /admin                     관리자 (ROLE_ADMIN)

  /_not-found                404
```

**전역 네비게이션에 들어갈 것**: 대시보드 · 라이브러리 · 담기 · 설정, 그리고 **관리자(조건부)**.
로그인 직후 도착지는 `/dashboard`.

## 2. 화면별 요구

### 2.1 `/` 랜딩

메뉴가 없는 유일한 앱 화면. **데이터를 거의 안 쓰므로 연출 자유도가 가장 높다.**

| 상태 | 화면 |
|---|---|
| 판정 중 | `GET /api/me` 응답 전. **여기서 깜빡임이 생긴다** — 인트로 연출이 이걸 덮는다 |
| 비로그인 | `[로그인]` `[회원가입]` `[Google로 시작]` |
| 로그인됨 | `[{닉네임}으로 계속]` `[로그아웃]` |

- 로그인/회원가입 버튼이 **세션을 죽이지 않는다.** 로그아웃은 명시적 버튼으로 분리했다
- `Google로 시작`은 fetch가 아니라 **브라우저 통째 이동** (`/oauth2/authorization/google`)
- API가 실패해도 비로그인 화면으로 그리면 되므로 **에러 상태가 필요 없다**

> **필요한 디자인**: 배경 연출 · 로고/워드마크 · 버튼 2~3개 · 인트로 타이밍.
> 3D/셰이더까지 가지 않아도 노이즈 그라디언트 + CSS로 레퍼런스 톤이 나온다.

### 2.2 `/login`

`POST /api/auth/login` — **JSON이 아니라 form 형식** (`email=...&password=...`)

| 응답 | 화면 |
|---|---|
| `200` | `/dashboard`로. 단 `withdrawalPending: true`면 `/restore`로 |
| `401 AUTHENTICATION_FAILED` | **비밀번호 오류와 없는 계정을 구분해 보여주면 안 된다** (NFR-S3). 한 문구 |
| `403 EMAIL_NOT_VERIFIED` | "메일 인증을 마쳐야 해" + **재발송 버튼**을 그 자리에 |

- 필드 2개 + 구글 버튼 + `비밀번호를 잊었어` 링크 + `회원가입` 링크
- **로그인 성공 시 CSRF 토큰이 새로 발급된다.** 갱신을 놓치면 직후 모든 쓰기가 403

### 2.3 `/signup`

`POST /api/auth/signup` — `{ email, password, nickname }`

- 비밀번호 **8~64자** (BCrypt가 72바이트 초과분을 버려서 상한이 있다)
- `409 CONFLICT` 이미 가입된 이메일 — **탈퇴 유예 중인 이메일도 여기 걸린다**
- 성공은 **자동 로그인이 아니다.** "메일 확인해" 안내 화면으로 전환된다

### 2.4 `/verify-email?token=`

도착하자마자 토큰을 자동 제출. 결과는 **성공/실패 두 가지뿐**.

- 실패 사유(없는 토큰 / 만료 / 이미 사용됨)를 **구분해 알려주지 않는다.** 한 문구
- 재발송 폼 — 응답이 **항상 202**라 "보냈어"만 보여준다. 실패 표시가 없다 (60초 스로틀)

### 2.5 `/password-reset` · `/password-reset/confirm?token=`

- 요청: 이메일 입력 → **항상 202**. "가입돼 있다면 메일이 갔어" 식 문구가 강제된다
- 확정: 새 비밀번호(8~64) → `204`. **성공하면 기존 세션이 전부 끊긴다** — 안내 필요

### 2.6 `/restore`

탈퇴 유예(30일) 중 로그인하면 도착. `ROLE_PENDING_DELETION`이라 **이 화면 말고는 전부 403**.

- `[복구할래]` → `POST /api/me/restore` · `[로그아웃]`
- ⚠️ **남은 유예 일수를 주는 API가 없다.** 표시하려면 백엔드에 필드 추가가 필요하다

### 2.7 `/dashboard`

| 타일 | 데이터 |
|---|---|
| 총 게임 수 · 완료 수 · 플레이 중 수 | `GET /api/backlog/facets` → `statuses` |
| 플레이 중 이름 리스트 | `GET /api/backlog?status=PLAYING` |
| 최근 플레이 5 / 최다 플레이 5 / 최고 별점 5 | `?sort=lastPlayed\|playtime\|rating&size=5` |
| ↳ "더 보기" | 같은 `sort`를 들고 `/library`로. 프론트 라우팅만 |
| 총 플레이 시간 | `GET /api/stats/playtime` ⚠️ |
| 월별 지출 꺾은선 | `GET /api/stats/spending/monthly` ⚠️ |
| 장르 분포 · 기간별 완료 수 · 지출 2축 | `/api/stats/{genres,completions,spending}` |

> ⚠️ **실데이터가 비어 있는 타일이 둘 있다.**
> `acquiredOn`이 76건 전부 null이라 **월별 지출은 빈 차트**, `playTimeHours`도 전부 null이라
> **총 플레이 시간은 0**이다. API가 깨진 게 아니라 데이터가 없는 것이다.
> → **이 두 타일의 빈 상태를 디자인하거나, 자리를 나중으로 미룰지 정해야 한다.**

> ⚠️ **통화를 절대 합치지 마라.** 지출은 `[{KRW, 16500}, {USD, 19.99}]` 형태로 온다.
> 환율 변환은 범위 밖(Phase 10)이라 **차트 축이 통화별로 갈린다.** 차트 디자인에 직접 영향.

### 2.8 `/library`

가장 밀도 높은 화면. **세 덩어리 — 툴바 · 사이드바 · 그리드.**

**툴바**
- 검색어 `q`
- 정렬 **5종**: `lastPlayed`(기본) `rating` `releasedOn` `name` `playtime`
- 뷰 전환(그리드/폴더)을 둘지는 디자인 판단

**사이드바 게임 목록 — `GET /api/backlog/names`** (전 항목 이름순, 페이징 없음, 신설)

**facets — `GET /api/backlog/facets` 한 방** (목록과 분리돼 있어 페이지 넘길 때 재호출 불필요)
```
tags[]  genres[]  statuses[]  devices[]  platformAccounts[]     ← 전부 count 포함
```
- **태그는 카드에 안 뿌린다.** 폴더/모음집처럼 묶는 탐색 수단이다 (스펙 §6.7)
- 사용 중인 것만 나온다 (안 붙은 태그, 삭제된 항목에만 붙은 태그는 빠짐)

**카드** — 커버 · 이름 · 장르 · 평점(있으면) · 상태 · **마지막 회차**(번호 · 시작일 · 종료일 · 기기)
- 회차가 0개면 `lastPlaythrough`가 **통째로 null** → 이 줄이 비는 카드 디자인이 필요
- 종료일 null = 진행 중

**페이징** — `page` `size`(서버가 1~100으로 clamp) `totalElements` `totalPages`

**빈 상태 2종** — ① 항목이 아예 없음(→ 담기로 유도) ② 필터 결과 0건(→ 필터 해제로 유도).
문구가 달라야 한다.

### 2.9 `/library/[entryId]`

**한 화면에 폼이 5개** 들어간다. 읽기는 한 방, 쓰기는 각각 따로다.

```
GET  /api/backlog/{id}                     ← 한 번에 전부
PUT  /api/backlog/{id}/personal-record     평점 · 플레이시간 · 메모
PUT  /api/backlog/{id}/overrides           이름 · 개발사 · 배급사 · 출시일 · 정가
PUT  /api/backlog/{id}/tags
PUT  /api/backlog/{id}/genres
POST /api/backlog/{id}/playthroughs   ·  PUT|DELETE /api/playthroughs/{id}
POST /api/backlog/{id}/acquisitions   ·  PUT|DELETE /api/acquisitions/{id}
```

**⚠️ 상태(플레이 중/완료/…)는 직접 못 고친다.** 회차와 취득에서 **파생**된다.
"상태 드롭다운"을 그리면 안 된다 — 상태를 바꾸려면 회차를 추가/수정해야 한다.

**⚠️ 정보가 3층이다.** `master`(IGDB 원본) → `overrides`(내가 덮어쓴 것) → `resolved`(실제 표시값).
`overrides`의 필드가 null/빈배열이면 "안 덮어씀"이다.
→ **"내가 고친 값"임을 시각적으로 구분할 장치가 필요하다.**

**그 외**
- 커버 업로드: `POST .../cover/upload-url` → R2로 PUT → `PUT .../cover`. 삭제도 있음
- 메모는 **마크다운 원문**이다 (42건이 `# 📝 총평` 헤더 + 중첩 불릿). 렌더 스타일이 필요
- 삭제 후 같은 게임을 다시 담으면 `409 REVIVABLE` → **되살리기 확인 다이얼로그**
- `timeToBeatHours`(IGDB 평균 클리어 시간)는 참고값 — 오버라이드 대상이 아니다
- **정가는 화면에 출력하지 않기로 했다** (스펙 §8.1). 표시하는 금액은 취득 가격뿐이다

### 2.10 `/add`

```
GET  /api/games?q=      IGDB 온디맨드 검색
POST /api/games         수동 등록
POST /api/backlog       담기
```
- **외부 API라 느리다.** 로딩 표시가 필수고, IGDB 장애 시 `502`가 온다
- 이미 담은 게임은 `409`, 삭제했던 게임은 `409 REVIVABLE`
- 검색 결과 행: 이름 · 출시일 · 출처(IGDB/직접 등록) · 커버 썸네일

### 2.11 `/settings`

섹션 5~6개짜리 긴 화면.

| 섹션 | API |
|---|---|
| 프로필 (닉네임 · 메모) | `PUT /api/me/profile` |
| 플랫폼 계정 | `/api/me/platform-accounts` CRUD + **되살리기** |
| 보유 기기 | `/api/me/devices` CRUD |
| 구독 | `/api/me/subscriptions` CRUD (서비스명 · 기간 · 요금 · 주기 · 활성) |
| 태그 · 장르 사전 | `PUT\|DELETE /api/me/{tags,genres}/{id}` — **이름 수정과 삭제만** |
| 계정 | 구글 연결(`/oauth2/authorization/google`) · 해제(`DELETE /api/me/google`) · **탈퇴**(`DELETE /api/me`) |

- 폼 선택지는 `GET /api/me/options` 한 방 (플랫폼 · 기기 · 에뮬 · 계정 · 구독 · 태그/장르 자동완성)
- **기기는 마스터 전체를 준다.** 보유 기기는 우선 표시일 뿐 제약이 아니다 (친구 집에서 빌려 플레이한 기록)
- **구글 해제는 비밀번호가 있어야 가능하다.** 없으면 로그인 수단이 하나도 안 남는다
- 탈퇴는 30일 유예 + **즉시 세션 종료**. 확인 단계가 필요하다

### 2.12 `/admin`

회원 목록 · 감사 로그 · 마스터 게임 수정/병합/재동기화 · 플랫폼·기기·에뮬레이터 마스터 관리.

- **마스터에 삭제가 없다.** 회차·취득이 참조하고 있어 지우면 과거 기록이 깨진다. 추가와 이름 수정만
- 병합 시 양쪽을 다 담은 회원이 있으면 `409` — 관리자가 먼저 정리해야 한다
- **화면을 숨기는 건 보안이 아니다.** 실제 방어선은 서버의 403이다

## 3. 전역 — 디자인할 때 신경 쓸 것

### 3.1 숫자와 단위

| | |
|---|---|
| **평점** | **0.0 ~ 100.0**, 소수 첫째 자리. 별 5개로 그리려면 `/20`. **`toFixed(1)` 필수** — `String(83.0)`이 `"83"`이 돼 실제로 터졌던 버그 |
| **금액** | 통화 3종(KRW/USD/JPY). **합산 금지.** 통화별로 따로 표시 |
| **날짜** | `YYYY-MM-DD` 문자열. **종료일 null = 진행 중** |
| **플레이 시간** | 시간 단위 숫자. ⚠️ 실데이터 전건 null |

### 3.2 고정된 값 목록

- **백로그 상태 6종** — 위시리스트 · 백로그 · 플레이 중 · 일시 중단 · 중도 포기 · 완료
  → **배지 6종의 색을 정해야 한다**
- **취득 방법 7종** — 구매 · 구독 · 무료 배포 · 선물 · 대여 · 체험판 · 미보유
- **입력 방식 4종** · **결제 주기 2종** · **정렬 5종**
- 한국어 라벨은 `src/lib/labels.ts`에 이미 있다

### 3.3 커버 이미지

**2단 폴백**이다. `coverUrl`(개인 업로드) → `coverImageId`(IGDB) → 기본 이미지.

```
//images.igdb.com/igdb/image/upload/{size}/{image_id}.jpg
t_thumb · t_cover_small(90×128) · t_cover_big(264×374) · t_720p · t_1080p
```

- **실데이터는 개인 커버 0건 / IGDB 커버 76건** — 사실상 이 경로만 탄다
- **비율이 약 1:1.42**다. 카드 그리드를 이 비율로 잡아야 잘리지 않는다
- 서버가 URL을 합쳐주지 않는 이유: 자리마다 크기가 달라야 해서 **크기 선택이 화면 몫**이다
- `public/default-cover.png`가 1.4MB짜리로 남아 있다 — 디자인 줄 때 같이 교체하자

### 3.4 상태 3종 세트가 화면마다 필요하다

| | |
|---|---|
| **로딩** | ⚠️ **Neon이 5분 유휴면 잠든다.** 첫 요청이 몇 초 걸린다 → 스켈레톤이 실제로 보인다 |
| **빈 상태** | 라이브러리 2종 · 대시보드 타일 2개(지출·플레이시간)는 **처음부터 빈 채로 시작** |
| **에러** | 백엔드가 `{ code, message }`로 통일해 준다. 특수 처리가 필요한 코드는 아래 |

```
401 UNAUTHORIZED         → /login
401 SESSION_EXPIRED      → /login (문구 구분)
403 FORBIDDEN            → 권한 없음
403 EMAIL_NOT_VERIFIED   → 인증 안내 + 재발송
403 (CSRF 누락)          → 토큰 갱신 후 재시도
409 REVIVABLE            → 되살리기 다이얼로그 (targetId · reviveUrl 포함)
502                      → IGDB 장애. 검색만 영향
```

### 3.5 아직 안 정한 것 — 디자인이 정해줘야 함

1. **다크 / 라이트 / 둘 다?** 레퍼런스는 전부 다크였고 마지막 스크린샷도 다크다
2. **반응형 어디까지?** 모바일까지 갈지, 데스크톱 고정일지. 라이브러리 사이드바가 갈림길
3. **라이브러리 뷰 전환**(그리드/폴더)을 유지할지
4. **대시보드의 빈 타일 두 개**를 그릴지 미룰지
5. **랜딩 톤 ↔ 앱 내부 톤**을 얼마나 이을지. 완전히 갈라도 되고(Linear 방식) 이어도 된다

### 3.6 참고

- 텍스트는 한국어지만 **게임 제목은 영문이 섞인다.** 폰트가 둘 다 소화해야 함
- 실데이터 76건 기준 분포: 완료 39 · 백로그 25 · 일시중단 8 · 플레이중 4
- 개인 장르 38종, 항목당 평균 2.3개 → **카드에 장르 칩이 2~3개** 들어간다고 보면 된다

## 4. 디자인 받은 다음 순서

1. **N-2 CORS/쿠키** — 백엔드. `allowCredentials=true` + 명시적 origin. 이거 없으면 아무것도 안 붙는다
2. **`src/lib/api.ts`** — fetch 래퍼 + `credentials: 'include'` + CSRF 헤더 부착 + 에러 코드 분기
3. **토큰 채우기** — `globals.css`의 `:root`에 디자인 토큰
4. **(public) 화면들** — API를 거의 안 타므로 여기부터가 쉽다
5. **(app) 화면들** — 라이브러리 → 상세 → 대시보드 → 담기 → 설정 → 관리자
