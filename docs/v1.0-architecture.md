## 0. 성격이 바뀌었다 — 이게 전부의 출발점

| | v0.1 (웹) | v1.0 (데스크탑) |
|---|---|---|
| 사용자 | 나 + 지인 몇 명 | **설치한 사람 각자** |
| 인프라 주인 | 나 | **설치한 사람 각자** |
| 계정 | 회원가입·승인·권한 | **없음** |
| DB | 내 Neon 하나 | **각자 고름** (또는 로컬 파일) |
| 스토리지 | 내 R2 | **각자 고름** (또는 DB 안에) |
| IGDB 키 | 내 키 | **각자 키** (없어도 됨) |

**"내 앱을 데스크탑으로 옮긴다"가 아니라 "남이 자기 인프라에 설치할 수 있는 프로그램을 만든다"다.**

이 전환 하나가 그동안 어정쩡했던 질문들을 전부 닫는다 —
회원을 남길까? **닫힘(로그인 없음).** 관리자는 누구? **닫힘(모두가 자기 것의 주인).**
승인은 왜? **닫힘(승인할 남이 없음).** 감사 로그는? **닫힘(물어볼 상황이 없음).**

**나는 클라우드 모드 사용자 1명일 뿐이다.** 특별대우 없음.
내 자격증명은 코드가 아니라 **내 기계의 설정 파일에만** 있다.

### 딸려오는 이득

- **앱이 유출돼도 샐 게 없다.** 키가 안 들어있으니까
- 배포 여부를 나중에 정해도 된다 — 구조가 이미 남에게 줄 수 있는 모양이다

## 1. 두 가지 모드

```
                  [ 같은 앱 하나 ]
                        │
        ┌───────────────┴───────────────┐
   로컬 모드                        클라우드 모드
   (아무 설정 없이 됨)                 (키를 넣어야 됨)

   DB   = H2 파일 (세이브파일)        DB   = PostgreSQL 호환 아무거나
   커버 = 로컬 covers/ 폴더            커버 = S3 호환 스토리지 또는 로컬 폴더
   IGDB = 키 있으면 검색,             IGDB = 〃
          없으면 수동 추가
```

**둘은 같은 코드다.** 갈리는 건 부팅할 때 주입되는 설정뿐이다.

### 왜 로컬 모드가 기본인가

첫 실행에 질문을 던지면 그 자리에서 앱을 닫는다.
**아무것도 안 물어보고 로컬로 뜬다.** 클라우드는 나중에 설정에서 옮기면 된다.

## 2. 기동 순서 — 백엔드를 늦게 띄운다

**⚠️ 이게 v1.0에서 가장 중요한 구조 결정이다.**

스프링은 부팅할 때 DataSource·커넥션풀·JPA 메타모델·Flyway를 **한 번에 조립한다.**
조립이 끝난 뒤에 DB를 바꾸는 건 엔진 돌아가는 중에 엔진을 가는 것과 같다
(라우팅 DataSource + EMF 재구축으로 억지로 되긴 하나 트랜잭션 수명·풀 생명주기·
Flyway 타이밍이 전부 엉킨다 — **여기서 며칠 태운다**).

그래서 **순서를 뒤집는다: 고르고 나서 띄운다.**

```
1. 일렉트론이 뜬다                       ← 백엔드 없음
2. 입구 화면을 파일에서 로드              ← 순수 프론트, DB 필요 없음
3. 사용자가 모드/키를 고른다
4. 빈 포트를 찾아 스프링을 spawn          ← 설정을 인자로 주입
   (여기가 "로딩 좀 됐다가" 3~5초)
5. 진단 통과하면 http://localhost:포트로 이동
```

**스프링은 매번 "이미 정해진 DB"만 본다 → 지금 코드가 그대로 돈다.**
모드 전환 = 백엔드 죽이고 다시 띄우기. (전환은 자주 일어나지 않는다)

### 경계가 여기서 갈린다

| 일렉트론 쪽 (네이티브) | 스프링 쪽 (앱 안) |
|---|---|
| 입구 화면 · 모드 선택 | 대시보드 · 라이브러리 · 상세 · 설정 |
| 세이브파일 목록 / 새로 만들기 | IGDB 키 |
| DB · 스토리지 자격증명 | 커버 위치 이전 |
| 폴더 경로 설정 | 마스터 게임 편집 |
| 백업 정책 | 데이터 내보내기(JSON) |

**기준은 "재시작이 필요한가"다.** DB·스토리지는 부팅 때 조립되므로 일렉트론 쪽,
IGDB는 런타임에 바꿔도 되므로 앱 안.

⚠️ **프론트가 두 오리진에서 뜬다** — 입구는 `file://`, 본 앱은 `http://localhost:포트`.
"스프링이 프론트를 전부 서빙한다"는 원칙의 **유일한 예외**다.

### 정적 내보내기의 두 걸림돌 — 둘 다 해결됨 (2026-08-27)

**① 동적 경로** — `output: "export"`는 `/library/[entryId]`에 `generateStaticParams()`를 요구하는데
entryId는 빌드 시점에 알 수 없다. **애초에 만들 수 없는 요구다.**
→ **쿼리로 옮겼다: `/library/detail?entry=57`.** 고칠 곳이 링크 3군데 + `useParams` 2군데뿐이었다.
`useSearchParams`는 프리렌더 때 값을 모르므로 **Suspense 경계**가 필요하다.

**② 빌드 시점에 굳는 API 주소** — `NEXT_PUBLIC_API_BASE`가 `http://localhost:8080`으로 박힌다.
일렉트론은 포트를 실행 시점에 고르므로 그 값이 틀린다.
→ **`lib/apiBase.ts` 한 곳으로 모으고, 데스크탑 빌드에서 상대 경로로 만든다**
(`NEXT_PUBLIC_SAME_ORIGIN=1`). 빈 문자열 대신 플래그를 쓴 이유는 빌드 도구마다
빈 환경변수를 "설정 안 함"으로 접기 때문이다.

**폴백은 `index.html`이 아니다.** App Router 정적 내보내기는 라우트마다 HTML을 떨구는데,
`index.html`은 **루트 라우트의 결과물**이라 그걸로 `/dashboard`를 열면 클라이언트 라우터가
`/`에서 시작한다. `StaticSiteConfig`가 `/dashboard` → `dashboard.html`로 이어 붙이고,
진짜 없는 경로만 `404.html`로 보낸다.

### ✅ 1단계 검증 완료 — 2026-08-27

실제로 만들어 돌려봤다 (`desktop/main.js`, Electron 33).

| 검증한 것 | 결과 |
|---|---|
| 빈 포트 자동 선택 | ✅ `net.createServer().listen(0)` → OS가 63881을 줌 |
| 스프링 spawn + **인자로 설정 주입** | ✅ `--server.port` · `--spring.profiles.active` |
| 스프링이 프론트까지 서빙 | ✅ 라우트마다 제 HTML (`/`·`/dashboard`·`/library/detail` md5가 전부 다름) |
| `/api/**`가 안 가려짐 | ✅ 401 정상 응답 |
| 로그를 파일로 | ✅ `~/Library/Application Support/starlog-desktop/backend.log` |
| **종료 시 백엔드도 죽음** | ✅ 일렉트론만 kill → java도 0개. **좀비 없음** |
| 기동 시간 | 약 15초 (jar 86MB, Neon 콜드스타트 포함) |

**즉 §2의 "고르고 나서 띄운다"가 실제로 성립한다.** 백엔드 코드는 한 줄도 안 바뀌었다.

### 딸려오는 자잘한 일 여섯

1. **개발 경로를 남긴다** — `bootRun` 하나로 뜨는 길이 없으면 백엔드 고칠 때마다 일렉트론을 거쳐야 한다
2. **좀비 프로세스** — 앱 종료 시 스프링을 확실히 죽인다. **윈도우에서 특히 잘 남아** 다음 실행의 포트를 문다
3. **포트** — 빈 포트를 찾아 인자로 넘긴다 (늦게 띄우므로 공짜로 해결)
4. **로그를 파일로** — stdout이 어디로도 안 가면 문제 생겼을 때 볼 게 없다
5. **프로세스 감시** — 백엔드가 도중에 죽으면 감지하고 안내
6. **기동 중 화면** — 스피너

## 3. DB — PostgreSQL 호환 + H2 파일

### 범위: PostgreSQL 계열만 받는다

Neon · Supabase · Railway · RDS · 자기 서버의 PG… **호스팅은 자유, 종류는 고정.**

**MySQL은 안 받는다.** 지금 마이그레이션이 ID를 전부
`bigint generated by default as identity`로 쓰는데 MySQL은 이 문법이 없다(`AUTO_INCREMENT`).
`bytea`도 없다(`BLOB`). 받으면 **마이그레이션이 두 벌로 갈라지고**, 그때부터 스키마를
바꿀 때마다 두 번 쓰고 두 번 테스트해야 한다. 혼자 만드는 앱에서 감당이 안 된다.

### 🟢 이식성은 이미 확인했다 (2026-08-27 실측)

- V1~V3 전체에 **PostgreSQL 전용 문법 0건** — `jsonb` · `serial` · `::캐스팅` ·
  `on conflict` · `create extension` 전부 없음
- 타입은 `bigint`/`timestamp`/`date`/`integer`/`text`/`boolean`/`bytea`만
- ID 전략 17개 전부 `bigint generated by default as identity` — **SQL 표준**이라 H2·PG 양쪽에서 그대로 돈다
- H2·PostgreSQL 드라이버가 **이미 둘 다 클래스패스에 있다** (지금도 프로필이 URL로 가른다)

**즉 지금 SQL 그대로 두 런타임을 다 태울 수 있다.**

### 붙었을 때 다섯 갈래

```
빈 DB                   → 자동으로 다 만들고 시드 넣음. 아무것도 안 물어봄
우리 스키마 · 버전 일치    → 그냥 씀
우리 스키마 · 구버전       → 자동 업그레이드 (로컬이면 직전에 백업, §5)
우리 스키마 · 더 최신      → "앱을 업데이트하세요" 경고 후 중단
남의 테이블이 있음         → "이 DB는 비어있지 않습니다" 경고 후 중단
                           → 이때만 [초기화] 버튼을 사람이 직접 누른다
```

**원칙: 만드는 건 자동, 지우는 건 절대 자동이 아니다.**

무료 티어 DB 하나를 여러 프로젝트가 나눠 쓰는 건 흔하다. "URL만 넣으면 알아서"를
하려다 `drop table`을 돌리면 **복구 불가**다.

⚠️ **탈출구: 스키마 지정.** PostgreSQL은 스키마를 나눌 수 있다. 설정에 `schema` 칸을
하나 주면 `starlog` 스키마에만 우리 테이블이 들어가고 **남의 테이블과 한 DB에서 공존한다.**
아무것도 안 지우고 다섯 번째 경우가 사라진다.

### 진단은 스프링이 한다

"연결 테스트"를 일렉트론(Node)에서 하려면 **PG 드라이버와 S3 SDK를 Node에도 또 넣어야**
한다. 드라이버가 두 벌이 되고 버전이 어긋나면 "일렉트론은 되는데 스프링은 안 되는" 상황이 난다.

→ **스프링이 부팅 아주 초기에 진단하고, 실패하면 구조화된 코드로 죽는다.**
일렉트론은 코드만 보고 한글 안내를 띄운다.

```
DB_UNREACHABLE       호스트를 못 찾음    → 주소 오타 / 인터넷
DB_AUTH_FAILED       비번 틀림
DB_NOT_EMPTY         남의 테이블이 있음   → 위 다섯 갈래
SCHEMA_TOO_NEW       앱이 옛 버전
STORAGE_AUTH_FAILED  S3 키 틀림
STORAGE_NO_BUCKET    버킷 없음
```

**에러 종류를 미리 정해두는 게 실제 일이다.** 안 하면 "연결 실패" 한 줄만 뜨는 앱이 나온다.

## 4. 🔑 커버 이미지 — 위치를 커버 한 장 한 장이 들고 있는다

### 문제

"스토리지가 어디인가"를 **설정으로 알면** 설정을 바꾸는 순간 기존 500장이 전부 미아가 된다.
S3 없이 쓰다 붙일 때도, 쓰다가 뗄 때도 곤란해진다.

### 해결

`CoverImage`에 `location` 칸을 준다.

```
location = LOCAL     → 바이트가 데이터 루트의 covers/ 폴더에
location = EXTERNAL  → 바이트가 S3에, storageKey가 주소
```

| 상황 | 무슨 일이 일어나나 |
|---|---|
| S3 없이 시작 | 전부 `LOCAL`로 쌓임 |
| 나중에 S3 붙임 | 기존 500장은 **그대로 `LOCAL`로 남아 잘 보인다.** 새 커버만 `EXTERNAL` |
| 옮기고 싶으면 | "커버를 S3로 옮기기" — 한 장씩 옮기고 그 행만 `EXTERNAL`로 |
| S3를 뗌 | "S3에서 가져오기" — 한 장씩 받아 `LOCAL`로 |

**한 장 단위인 게 전부다.** 중간에 끊겨도 300장은 S3, 200장은 로컬인 채로 **둘 다 멀쩡히 보인다.**
다시 눌러 이어서 하면 된다.

이전이 중단돼도 **조용히 둔다.** 설정 화면에 "로컬 380장 / S3 120장"만 보여주면
사용자가 알아서 판단한다.

### DB 저장(bytea)은 폐기했다 — 2026-08-27

원래 `location = DB`를 두려 했다. **유일한 근거가 "세이브파일 하나면 온전하다"였는데,
개인 커버와 스크린샷을 백업에서 빼기로 하면서(§6) 그 근거가 사라졌다.**

남는 건 단점뿐이었다 — DB 용량(200KB × 500 ≈ 100MB, Neon 무료가 0.5GB)과
바이트 스트리밍 코드. **`FileStoragePort`에 로컬 폴더 구현체 하나를 더하는 쪽이 싸다.**

⚠️ **대가 하나** — 클라우드 모드에서 S3 없이 쓰면 **개인 커버가 그 기계에서만 보인다.**
맥북에서 올린 커버가 윈도우에서 안 보인다. → **"기기 두 대에서 공유하려면 S3가 필요합니다"로 안내.**
(IGDB 마스터 커버는 원래 IGDB 주소를 쓰므로 어디서든 보인다)

### ⚠️ 업로드 경로가 두 갈래가 된다

지금은 **프리사인드**다 — 백엔드가 서명된 주소를 주고 **브라우저가 S3로 직접 PUT**한다.
로컬 폴더에는 서명할 주소가 없다. **바이트가 백엔드를 통과해야** 한다.

- 백엔드에 **멀티파트 업로드 엔드포인트** 신설
- **프론트가 분기** — S3면 프리사인드, 로컬이면 직접 전송
- 내려주는 경로도 분기 — S3는 `publicUrl`, 로컬은 `GET /api/covers/{id}` 스트리밍
  (스프링이 같은 기계에 있으므로 로컬 폴더를 그냥 읽는다)

### 스토리지는 S3 호환이면 아무거나

`S3CompatibleFileStorage`가 `endpointOverride`를 받는다 →
AWS S3 · Cloudflare R2 · MinIO(자기 서버) · Backblaze B2 · Wasabi 전부 붙는다.
사용자는 `endpoint / accessKey / secretKey / bucket` 네 개만 넣는다.

## 5. 폴더 구조 — 데이터 루트 하나

### 자격증명·설정은 앱데이터에 고정, 나머지는 통째로 옮길 수 있다

```
<OS 앱데이터 폴더>            ← 고정. 못 옮긴다
  settings.json               데이터 루트 위치 · 창 크기 · 마지막 모드
  connections.json            DB·스토리지 자격증명 세트들

<데이터 루트>                 ← 기본은 앱데이터 안. 통째로 옮길 수 있다
  saves/
    내기록.mv.db              지금 쓰는 것. 세이브 하나당 파일 하나, 항상 최신만
    실험용.mv.db
  backups/
    내기록/
      2026-08-27_1430.mv.db   오래된 것부터 밀려난다
  covers/                     개인 업로드 커버 (location = LOCAL)
  media/
    hollow-knight/            게임별 스크린샷 (§10-1)
    ratchet-clank-rift-apart/
```

**설정은 "데이터 루트 어디?" 하나뿐이다.** 기본값이 앱데이터 안이라 아무것도 안 건드려도 되고,
HDD로 옮기고 싶으면 그 한 칸만 바꾸면 **세이브·백업·커버·스크린샷이 통째로 따라간다.**

**자격증명을 앱데이터에 고정하는 게 중요하다** — 데이터 루트를 외장이나 공유 폴더로 옮겼을 때
DB 비밀번호가 딸려가면 안 된다.

**설정 파일이 없거나 깨졌으면** 앱 실행 시점에 안내하고 **바로 기본 파일을 만든다.**
(형식 불일치·이름 변경·삭제 전부 같은 처리)

### 세이브파일 = H2 DB 파일 그 자체

백업 JSON이 아니다. **고르면 그 파일이 곧 현재 DB다.** 저장 버튼이 없다.
게임 세이브파일과 같은 은유이고, 그래서 "내보내기(백업)"가 별개 개념으로 깨끗하게 갈린다.

**백업이 생기는 계기 셋**
1. 스키마 자동 업그레이드 **직전** — 올리면 그 파일은 옛 앱에서 영영 못 연다
2. 사용자가 수동으로
3. **클라우드에서 뽑을 때** (§6)

**한도는 개수와 용량 둘 다 건다** — "최대 N개 **또는** 총 X GB, 먼저 걸리는 쪽".
개수만 걸면 큰 파일이 디스크를 먹고, 용량만 걸면 작은 파일이 무한정 쌓인다.
**가장 최신 하나는 어떤 경우에도 지우지 않는다.**

### ⚠️ 함정 — 쓰는 중인 H2 파일을 `cp`로 복사하면 손상된다

백엔드가 그 DB를 열어놓고 조금씩 쓰는 중이다. 그냥 긁으면 트랜잭션 중간 상태가
찍혀 **열리지도 않는 파일**이 나온다.

→ **H2의 `BACKUP TO` 명령을 쓴다.** 온라인 백업을 지원해 앱이 도는 중에도
일관된 스냅샷을 뜬다. 어려운 게 아니라 **`cp`를 쓰면 안 된다는 걸 알고 있어야** 하는 문제다.

## 6. 🔑 클라우드 백업 = 로컬 세이브파일 만들기

세이브파일이 H2 파일이므로, **"클라우드 백업"이 곧 "로컬 세이브파일 생성"이다.**

```
클라우드 DB  ──→  saves/내기록_2026-08-27.mv.db
```

**복원이라는 과정이 아예 없다.** 만든 파일을 로컬 모드에서 열면 그 순간부터 쓸 수 있다.

기술적으로도 쉬운 쪽이다. §2의 "런타임 DB 전환"이 어려웠던 건 **살아있는 JPA를 갈아끼워야**
해서인데, 이건 **읽기 소스 + 새로 만드는 타겟**이라 JPA를 안 거치고 JDBC로 행을 복사하면 된다.

### 백업에 들어가지 않는 것 — 2026-08-27 결정

| | 백업(.mv.db)에 | 이유 |
|---|---|---|
| 백로그·회차·취득·메모·태그 등 DB 내용 | ✅ | 본체다 |
| **개인 업로드 커버** | ❌ | `covers/` 폴더에 따로 있다 |
| **스크린샷** | ❌ | 장당 2~5MB, 수백 장이면 GB. 백업이 감당 못 한다 |

**대신 이 셋이 같은 데이터 루트 아래 나란히 있다** (§5) —
루트 폴더를 통째로 복사하면 전부 따라간다. **작은 것은 안에, 큰 것은 옆에.**

⚠️ 그래서 **"세이브파일 하나면 온전하다"는 성립하지 않는다.**
온전한 단위는 **데이터 루트 폴더**다. 이 문장이 §4에서 DB 저장을 폐기한 근거이기도 하다.

### JSON 내보내기는 남긴다

2026-08-27에 이미 만들었다(`GET /api/me/export`). 성격이 다르다:

| | H2 파일 백업 | JSON 내보내기 |
|---|---|---|
| 복제 | DB 내용 전부 | 자격증명·파생상태·id 제외 |
| 바로 실행 | ✅ | ❌ (넣어야 함) |
| 사람이 읽음 | ❌ | ✅ |
| 버전 안정성 | H2 버전에 묶임 | 포맷 버전으로 관리 |

**H2 파일이 주력, JSON은 "이 프로그램 밖으로 나가는 문".** 이미 만들었으니 비용 0.

## 7. 자격증명 — 평문 저장 (명시적 결정)

OS 앱데이터 폴더에 **두 파일로 나눠** 둔다 (§5).

| 파일 | 무엇 | 남에게 보여도 되나 |
|---|---|---|
| `settings.json` | 데이터 루트 위치 · 창 크기 · 마지막 모드 | 된다 |
| `connections.json` | DB·스토리지 자격증명 세트들 (여러 개, 삭제 가능) | **절대 안 된다** |

**나누는 이유** — 한 파일이면 "이건 복사하지 마"가 규칙으로 성립하지 않는다.
매번 안을 들여다보고 골라내야 한다. **파일이 갈려 있어야 규칙이 선다.**

```json
// connections.json
{ "profiles": [
    { "name": "내 Neon",
      "db":      { "url": "...", "user": "...", "password": "..." },
      "storage": { "endpoint": "...", "accessKey": "...", "secretKey": "...", "bucket": "..." } }
] }
```

> **OS 키체인 암호화(일렉트론 `safeStorage`)를 검토했고 쓰지 않기로 했다.**
> 사용자 결정 (2026-08-27): **분실·유출은 개인 몫.**
> 근거 — 기기를 옮길 때마다 다시 입력해야 하고, 리눅스처럼 키링이 없으면 폴백 경로가
> 늘어난다. 혼자 쓰는 프로그램에서 그 복잡도를 지불하지 않는다.

⚠️ **그래서 지켜야 하는 것 — `connections.json`이 딴 데 실려 나가면 안 된다.**

- `.gitignore`에 반드시
- **앱데이터에 고정**한다. 데이터 루트를 외장·공유 폴더로 옮겨도 따라가지 않는다
- **백업 폴더·세이브파일·JSON 내보내기 전부 제외** (지금도 자격증명은 안 담는다 — 유지)

### 스프링은 이 파일을 모른다

**설정을 읽는 건 일렉트론뿐이고, 스프링은 받은 인자대로만 뜬다.**

```
일렉트론이 띄울 때 → connections.json 읽어서 인자로 넘김
개발자가 띄울 때   → application-local.yml 이 그 역할
```

스프링 입장에서 둘이 구분되지 않는다 → **스프링 코드에 "일렉트론용 분기"가 하나도 안 생기고,
개발할 때 `bootRun` 한 줄로 뜨는 길이 그대로 산다.**

## 8. 인증 없음

**로그인 화면이 없다. 회원 개념이 사용자에게 노출되지 않는다.**

DB에 붙는 열쇠는 **앱이 들고 있는 자격증명**이지 비밀번호가 아니다.
앱을 실행할 수 있는 사람은 이미 DB 전체에 접근한 것이고, 그 위에 로그인을 얹는 건
**자기 집 방문에 자물쇠를 하나 더 다는 것**이다. 열쇠는 이미 그 사람 손에 있다.

### 이음매는 파일 하나다

`@LoginMember`를 쓰는 컨트롤러가 18개인데 값이 전부
`LoginMemberArgumentResolver` 한 곳을 지난다. 여기를 "항상 소유자 memberId를 돌려준다"로
바꾸면 **컨트롤러 18개가 한 줄도 안 바뀐다.** I-3에서 헤더인증 → 시큐리티로 갈아탈 때도
시그니처가 하나도 안 바뀌었다. 검증된 이음매다.

소유자 memberId는 **앱이 뜰 때 없으면 만들고 그걸 쓴다** (`AdminBootstrap` 자리에 얹음).
새 기계에서 처음 켰을 때 아무것도 안 해도 뜬다.

### Member 엔티티는 남긴다 (지우지 않는다)

실측: `memberId`를 만지는 백엔드 파일 **80개 / 584줄**, DDL **45줄**,
**`member_id`가 낀 유니크 제약 9개**, 테스트 15파일.

**얻는 것은 컬럼 하나가 사라지는 것뿐이다.** 성능·용량 차이 0.
게다가 유니크 제약의 **의미가 바뀐다** — `(member_id, name)`("회원 안에서 유일")이
`(name)`("전역에서 유일")이 되고, 이건 되돌리기 어려운 스키마 결정이다.

→ **열은 남기고 값은 항상 1.** 지운다면 웹을 완전히 내린 뒤 청소 단계에서.

## 10. v1.0에 새로 들어가는 기능

### 10-1. 스크린샷 (영상은 보류)

스펙 `spec-v1.5.md` FR-MED-04에 **COULD로 이미 있던 항목**이다. v1.0에서 MUST로 올린다.

> **영상은 v1.0 범위에서 뺐다** (2026-08-27). 일렉트론은 크로미움이라 `.mkv`·HEVC를
> 재생하지 못하는데 게임 녹화는 mkv가 흔하다. 썸네일 추출에도 별도 도구가 필요하다.
> 스크린샷만으로 시작한다.

**파일을 우리 폴더로 복사한다.** 경로만 참조하지 않는다 —
탐색기에서 알아보게 게임별로 정리하는 게 목적이고, 그러면 원본이 사라져도 앱에는 남는다.

```
<데이터 루트>/media/hollow-knight/2026-08-27_보스전.png
```

#### 폴더 이름 규칙 (slug)

**IGDB 영문 이름 기준.** 전부 소문자, 공백·특수문자는 하이픈.

```
Ratchet & Clank: Rift Apart  →  ratchet-clank-rift-apart
Hollow Knight                →  hollow-knight
```

빠지기 쉬운 네 가지를 함께 처리한다:

| | 처리 |
|---|---|
| 연속·앞뒤 하이픈 | `ratchet---clank--rift-` → `ratchet-clank-rift` |
| **직접 등록 게임**(영문 이름 없음) | 입력한 이름 그대로. 한글은 유지하고 공백·금지글자만 하이픈 → `젤다의-전설` |
| slug가 **빈 문자열**이 되는 경우(이름이 특수문자뿐) | `game-{id}` |
| **윈도우 예약어** `con` `aux` `nul` `prn` `com1~9` `lpt1~9` | 폴더로 못 쓴다 → `game-con` |

- 완전히 겹치면 뒤에 번호 (`hollow-knight-2`)
- **정해진 폴더 이름을 마스터 게임(`Game`)에 저장한다** — 게임 이름을 바꿔도 폴더를 계속 찾는다
- **폴더는 스크린샷을 처음 붙일 때 만든다** — 게임 담을 때마다 만들면 빈 폴더가 수백 개 생긴다
- 마스터 게임 하나당 항목 하나라(중복 방지) 게임 기준 폴더로 충분하다
- 게임 상세에 **경로 표시 + 탐색기에서 열기** 버튼. 일렉트론에서만 보인다(웹에서는 숨김)

#### 보기와 삭제만 준다

- 썸네일을 **클릭하면 확대 팝업**
- **선택 모드로 일괄 삭제**
- 캡션·순서·정렬은 주지 않는다 — 파일명과 시간순으로 충분하고, 주면 편집 UI가 딸려온다

#### 탐색기 열기는 스크린샷 폴더만이 아니다

일렉트론은 아무 로컬 경로나 탐색기로 열 수 있다. 설정 화면에서
**데이터 루트 · `saves/` · `backups/` · `covers/`** 각각에 [열기] 버튼을 단다 —
세이브와 백업은 사용자가 직접 만질 일이 있다.

#### 붙이는 방법 셋 — 커버도 같이 고친다

**드래그 앤 드롭 · 파일 고르기 · 붙여넣기(Ctrl+V)** 를 전부 지원한다.
게임 스크린샷은 캡처 직후 클립보드에 있는 경우가 많아 Ctrl+V가 가장 빠르다.

⚠️ **지금 커버 업로드에 실제 버그가 있다** (2026-08-27 확인).
`CoverDialog`에 드래그 앤 드롭이 **아예 없고** `<input type="file">` 하나뿐인데,
박스를 넓게 스타일링해둬서 **아무 데나 눌러도 될 것 같지만 왼쪽 작은 버튼만 동작한다.**
(드롭이 되는 것처럼 보였던 건 브라우저가 파일 input에 대해 기본 제공하는 동작이다)

→ 커버·스크린샷 둘 다 **드롭 영역 전체 클릭 + 드래그 중 호버 표시 + 붙여넣기**로 새로 만든다.

### 10-2. 마스터 게임 일괄 동기화

IGDB에서 마스터 정보를 한꺼번에 최신화한다.

🟢 **`GameResyncService`와 `POST /api/admin/games/{gameId}/resync`가 이미 있다.**
일괄 동기화는 **그걸 1초 간격으로 도는 루프**다. 새로 만들 로직이 거의 없다.

#### 진행 상태를 저장하지 않는다 — `lastSyncedAt`이 이미 상태다

```
동기화 대상 = lastSyncedAt이 3개월 넘은 IGDB 게임
50개였는데 3개 끝났으면 → 남은 게 47개
화면의 "3 / 50" = 그 숫자를 세면 나온다
```

**중간에 끊겨도 다시 누르면 남은 47개만 잡힌다.**
재개 로직도, 상태 테이블도, 롤백도 필요 없다. 진행 상태를 따로 안 두는 게 아니라
**동기화 시각 자체가 이미 상태라서 둘 게 없다.**

- **3개월은 고정**이다 (설정으로 빼지 않는다 — 설정 하나가 늘면 화면과 저장할 곳이 같이 는다)
- 누르면 **어떤 게임이 대상인지 팝업 목록으로 보여주고 승인**을 받는다
- 마스터 게임 목록 화면에 **원형 로딩 애니메이션 + `3 / 50`**
- `GameSource.MANUAL`은 대상에서 제외 — 원본이 없다
  (지금 단건 API는 400을 던진다. 일괄에서는 애초에 목록에 안 담는다)

### 10-3. 마스터 게임 삭제

지금은 삭제 경로가 없다. **참조가 있어도 지울 수 있게 하되 경고를 세게 한다.**

중복 방지가 있어서 **참조는 0건 아니면 1건이다.**
그래서 "누가 쓰고 있나"를 물을 필요가 없고, **"이 게임의 기록(평점·메모·회차·취득)도 함께
사라집니다"** 한 줄이면 충분하다.

- **휴지통을 거치지 않고 완전 삭제.** 마스터를 지우는 건 "이 게임 자체를 없앤다"는 뜻이라,
  항목만 휴지통에 남기면 되살릴 마스터가 없어 앞뒤가 안 맞는다

### 10-4. MANUAL 게임의 재동기화 버튼 숨기기

직접 등록한 게임은 원본이 없어 재동기화가 의미 없는데 버튼이 보인다.
→ 프론트에서 숨긴다. **백엔드의 400은 그대로 둔다** — 서버는 클라이언트를 믿지 않는다.

## 10-5. 정렬 규칙 — DB에 맡기지 않는다

**확정 규칙: 영문 먼저(대소문자 무시), 그다음 한글.**

DB 콜레이션으로는 못 맞춘다. H2와 PostgreSQL이 다르고, 클라우드 DB는 사용자가
아무거나 고르므로 더더욱 보장할 수 없다.

→ **정렬 전용 칸을 두고 앱이 계산해 넣는다.**

```
8-Bit Adventures  →  0|8-bit adventures
.hack             →  0|.hack
Zelda             →  1|zelda
apple             →  1|apple
가디언             →  2|가디언
```

- 앞 숫자가 그룹 — `0` = 숫자·기호, `1` = 영문, `2` = 한글, `3` = 그 외
- 뒤는 소문자로 낮춘 이름
- `order by` 이 칸 하나면 **어느 DB에서든 같은 순서**가 나온다
- 갱신 지점은 이미 있다 — `BacklogEntry.refreshDisplayName()`에 한 줄 얹는다

> 태그·플랫폼·장르·회사 이름 정렬은 **이미 자바에서**(`String.CASE_INSENSITIVE_ORDER`) 한다.
> DB에 맡기는 건 게임 이름 하나뿐이라 손댈 곳이 좁다.

## 10-6. V4 마이그레이션에 들어갈 것

웹을 먼저 내리므로(§12) 한 번에 올린다.

**V4는 이미 나갔다** (2026-08-27) — `play_time_hours integer → numeric(7,2)` 하나뿐이다.
캘린더 임포트가 급해서 먼저 쪼갰다. 나머지는 각 기능을 만들 때 V5·V6로 나간다.

| 마이그레이션 | 대상 | 칸 | 용도 |
|---|---|---|---|
| ✅ **V4** | `BacklogEntry` | `play_time_hours` | `integer` → `numeric(7,2)` |
| V5 | `CoverImage` | `location` | `LOCAL` / `EXTERNAL` (§4) |
| V5 | `Game` | `mediaFolder` | 스크린샷 폴더 이름, nullable (§10-1) |
| V5 | `BacklogEntry` | `displayNameSortKey` | 정렬 키 (§10-5) |

기존 행은 전부 채워야 한다 — 커버는 `EXTERNAL`(지금 R2), 정렬 키는 재계산,
`mediaFolder`는 null로 두고 필요할 때 만든다.

> **쪼갠 게 결과적으로 맞았다.** V4 하나만 나가면서 Flyway·Hibernate `validate`·
> 실데이터 반영이 한 번에 검증됐고, 실패했어도 되돌릴 범위가 작았다.

## 10-7. 창 크기와 반응형

**결론: 전체화면 강제도, 게임식 축소도 아니다. 최소 크기를 정하고 기본은 최대화.**

```
기본 창    최대화 (전체화면 ❌ — 멀티태스킹이 안 된다)
최소 크기  1280 × 800   → 그 아래로는 못 줄인다
창 크기    settings.json에 기억
```

### 실측 — "반응형 안 함"이 생각보다 안 나쁘다 (2026-08-27)

| | |
|---|---|
| 고정 px 폭 | **딱 2개** — `MonthlySpendingChart`의 `min-w-[640px]`, `DataTable`의 `min-w-[520px]`. **둘 다 의도된 가로스크롤용** |
| 반응형 브레이크포인트 | **35군데 사용 중** (`sm` `md` `lg` `xl` `2xl`) |
| 컨테이너 | `max-w-*` + 유동 폭 |

**1920 고정 캔버스로 짠 게 아니다.** Tailwind 기본이 유동이라 이미 늘고 줄어든다.
"반응형 안 했다"는 **모바일을 안 챙겼다**는 뜻이지 1280에서 무너진다는 뜻이 아니다.

→ **최소 폭을 1280으로 막으면 1280~1920 범위만 보면 되고, 깨지는 화면만 골라 고치면 된다.**

### ❌ CSS `scale`로 축소하는 방식은 비싸다

게임처럼 "1920 기준으로 그리고 창 크기에 맞춰 통째로 축소"하는 안을 검토했고 **버렸다.**

**우리 팝업이 화면 좌표를 실측한다.** `anchorPosition.ts`의 `placeBelow()`가 요소의 실제
좌표를 재서 팝업을 배치하고 화면 밖이면 뒤집고 클램프한다. DateField · Dropdown · Combobox가
전부 이걸 쓴다 (2026-08-27 리뷰에서 고친 바로 그 코드다).

조상에 `transform: scale`이 걸리면 **두 가지가 동시에 깨진다:**
1. `position: fixed`가 화면이 아니라 **그 transform 조상 기준**이 된다
2. `getBoundingClientRect`가 **축소된 좌표**를 돌려줘 계산이 어긋난다

→ 팝업 위치 코드를 전부 다시 손봐야 한다. 거기에 **WebGL 배경이 흐려지고**,
1280 창이면 0.67배라 **12px 글씨가 8px이 되어 못 읽는다.**
게임은 UI가 원래 크게 그려져 있어 축소가 먹히는 것이고, 이 앱은 텍스트 밀도가 높다.

### ⚠️ 대가 하나

**1920 모니터에서 좌우 반반 분할(960px)이 안 된다.** 4K나 21:9면 된다.
필요해지면 최소 폭을 960까지 내려야 하는데 **사이드바 접기 같은 진짜 반응형 작업**이 붙는다.
→ **1280으로 시작하고, 쓰다가 아쉬우면 그때 별도 작업으로.**

## 11. 알려진 위험

### ✅ 정렬 콜레이션 — 해결됨 (§10-5)

전에 "H2와 PostgreSQL이 이름순을 다르게 정렬한다"를 위험으로 올려뒀다.
**정렬 키 칸을 두기로 하면서 DB에 의존하지 않게 됐다.**
Neon 콜레이션을 확인할 필요도 사라졌다.

### 남은 것

- **두 런타임을 다 테스트해야 한다** — 대부분은 H2(빠르다), **DB마다 갈릴 수 있는 것만**
  실 PostgreSQL(Testcontainers)에서: 정렬·파셋 집계·통계 쿼리·스키마 검증
- **JRE는 플랫폼별이다** → 윈도우 빌드는 윈도우에서. 크로스 빌드는 고생길
- **스키마 다운그레이드는 불가** — 새 앱으로 연 세이브파일은 옛 앱에서 못 연다 (§5의 백업이 방어)
- **클라우드 + S3 없음이면 개인 커버가 기기 간 공유되지 않는다** (§4)
- `LICENSE`가 없다. 남에게 줄 거면 필요하다 (MIT 예정)

**원래는 "일렉트론이 두 기계에서 다 돈 뒤"였다. 뒤집었다.**
